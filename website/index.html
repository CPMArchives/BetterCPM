01 / The operating system

Familiar by design. Better by architecture.

BetterCP/M retains the familiar CP/M world of drives, user areas, transient programs and BDOS services, while providing a clean, documented foundation for its continued evolution.

[01] COMPATIBILITY

Your CP/M environment

A CP/M 2.2 compatibility baseline backed by documented requirements and executable tests.

[02] COMMAND LINE

A more capable prompt

Numeric command PATH, persistent command history, optional multiple command lines and system variables.

[03] ORGANIZATION

Named directories

Optional named directories make it easier to navigate drives and user areas without abandoning the CP/M model.

[04] EXTENSIONS

Extend the system

Loadable CPX commands and relocatable RSX services extend functionality without putting every feature in the resident core.

[05] CONSOLE

Terminal flexibility

Integrated ADM3A, VT52 and ANSI terminal personalities through TCAP 2.0.

[06] STORAGE

Manage your disks

Four physical drives, runtime disk-format assignment, and CONFIG, DUP, SYSBUILD and SYSGEN tools.

04 / Under the hood

An operating system you can understand.

BetterCP/M is built around explicit interfaces, inspectable state, reproducible builds and portable hardware boundaries. It is intended to be as attractive to system developers and hardware builders as it is to ordinary CP/M users.

ARCHITECTURE

Clear system boundaries

CCP, BDOS, BIOS and extensions have documented responsibilities. Machine-specific support is separated from portable system code.

DEVELOPMENT

Build on CP/M itself

Native CP/M development and system-generation paths coexist with modern cross-development tools.

QUALIFICATION

Compatibility by evidence

A dedicated CP/M 2.2 compatibility suite, subsystem regression tests and retained release evidence support the compatibility claims.

06 / The project

Historically grounded. Forward looking.

The goal is not simply to reproduce Digital Research CP/M source code, but to provide a well-specified, practical environment for small 8-bit systems. Design and acceptance are human-directed; AI assists implementation, analysis, testing and documentation.
