# BetterCP/M 1.3: MCL semantics proposal for maintainer review

Status: maintainer-approved design; implementation proceeds in reviewable stages. Baseline: v1.2
`a496016b8f6430bc96ced32b339629bd566425e1`.

## Recommendation

Support one interactive sequence, separated by unquoted semicolons. Preserve
the existing 127-character input limit and CP/M command tails. Keep one bounded
128-byte pending-remainder object. Resume after ordinary warm returns; discard
on errors and Ctrl-C that BetterCP/M can identify. Retain SUBMIT priority.
No exit-status protocol, nesting, FLOW, conditional execution or general queue.

## Input and splitting contract

MCL applies to interactive lines, including history-recalled lines, when its
owner is enabled. With MCL disabled, preserve v1.2 semicolon handling. Do not
apply MCL splitting to STARTUP or submitted records in 1.3; startup variables
can still be defined through STARTUP/SUBMIT. No line creates a second pending
sequence while another is active because pending work precedes interactive input.

Use `;` outside ASCII double quotes as separator. Double quotes toggle quoted
state and remain unchanged in the dispatched segment. Single quotes and
backslashes have no new escaping role. A doubled double quote toggles twice;
there is no C-style escape language. Validate balanced double quotes across
the entire interactive line before dispatching its first segment; an unmatched
quote rejects the line and queues nothing. This introduces explicit syntax
only when MCL is enabled; it does not alter application command-tail quoting.

Skip empty and whitespace-only segments. Preserve the selected segment's
existing CCP whitespace/tail processing; the splitter must not strip quotes or
rewrite argument text. An all-empty sequence does nothing. Examples:

| Input | Selected commands |
| --- | --- |
| `A;B;C` | A, B, C |
| `A;;B` / `;A;` | A then B / A |
| `SEARCH "A;B" *.TXT;DIR` | SEARCH with unchanged quoted argument, then DIR |
| `SEARCH "A;B` | Error; no command dispatched |

Record the original accepted interactive line once in HISTORY, before variable
expansion; do not record each extracted segment. Preserve the original case
handling rules in CCP and history. History behavior for non-MCL lines remains
unchanged. No synthetic pending input is exposed to BDOS program-input calls.

## Exact persistent object and state machine

| Offset | Bytes | Meaning |
| --- | ---: | --- |
| 0 | 1 | Pending text length, 0–125 |
| 1 | 1 | State: 0 empty; 1 pending; other values invalid |
| 2 | 126 | Unexpanded pending remainder; unused bytes zero |

Canonical empty object: all 128 bytes zero. State 1 requires length 1–125,
printable input text, zero unused bytes and balanced double quotes. No NUL
terminator is required within the length-delimited text. Payload validation
must happen before copying or parsing, including after reconstruction.

For a 127-character input, consuming at least one command character and one
separator leaves at most 125 pending characters. Leading/empty segments only
reduce that bound. Only the unexecuted remainder is copied into the object;
the complete original line and current command remain reconstructible data.

Before dispatch, extract a segment into the normal CCP buffer and commit the
remaining raw text to PDS. Clear state before editing the object, then publish
state 1 last if text remains; canonicalize empty after the final extraction.
The commit path must not invoke console/disk services that can warm-abort
halfway through an update. No persistent pointers or running-process IDs.
Byte-copying this owner payload is bounded queue maintenance, not PDS resizing.

```
EMPTY --accepted interactive sequence--> commit remainder, dispatch first
PENDING --next command acquisition-----> commit shorter remainder, dispatch next
PENDING --ordinary warm reconstruction-> validate, retain pending state
PENDING --recognized abort/error-------> EMPTY, return to ordinary acquisition
ANY --cold boot-----------------------> EMPTY
```

Malformed owner payload clears MCL and prints a diagnostic; no queued command
runs. Invalid PDS metadata follows the PDS proposal's cold-boot-required stop.

## Warm return and abort policy

The source cannot identify universal program success. In `gateway.mac`, the
protected COM handoff pushes the current page-zero warm target before entering
0100h. `CCP_GO` and `CCP_JUMP` do likewise. `SYS_WARM` reconstructs through one
path. BDOS Function 0 and application `JP 0000h` are conventional exits; requiring
a new success signal or treating all WBOOT as cancellation would break MCL's
intended sequential execution for existing software.

| Observed event | Proposed action |
| --- | --- |
| Core/CPX command returns through normal handled path | Continue |
| Transient RET | Continue after reconstruction |
| Transient BDOS Function 0 or JP 0000h | Continue after reconstruction |
| BIOS warm entry without a recognized abort marker | Continue |
| CCP unknown command, invalid command syntax caught by CCP, load failure | Discard remainder |
| Variable undefined/malformed/overflow failure | Discard remainder; do not dispatch segment |
| Ctrl-C that triggers an existing CCP/BDOS warm-abort path | Latch cancellation; discard after validated reconstruction |
| BDOS disk-error Ctrl-C abort | Latch cancellation; discard after validated reconstruction |
| Application prints its own error and exits normally | Continue: no portable error signal |
| Application handles raw Ctrl-C itself and jumps to warm boot | Continue: indistinguishable from normal application exit |
| Cold boot | Discard remainder |

The subsequently approved [integration amendment](1.3-MCL-INTEGRATION-REVIEW.md)
replaces immediate resident clearing: recognized BDOS abort sites set bit 2 of
the existing CPTFLAGS byte and retain their existing warm path. Reconstruction
validates PDS, clears the enabled MCL owner and consumes the latch before any
queued dispatch. CCP errors clear it directly through the validated transient
helper. No additional resident state byte is allocated. See the
[implementation and measured costs](1.3-MCL-IMPLEMENTATION.md).

Relevant production sites are in `src/bdos/unified.mac`: cooked console input,
pause/output checks, buffered input Ctrl-C, and `UB_SECKEY` disk-error abort;
also `ccp.mac:CCP_EDWBOOT`, explicit CCP error paths and loader failures.
Do not patch BDOS Function 0 to cancel unconditionally. Do not change application
page-zero interception semantics to install a completion trampoline. Update
production paths, not only the separate scaffold in `dispatch.mac`.

CPX dispatch currently reports handled/unhandled rather than a universal command
result. Do not invent FLOW-style status propagation. A CPX command that emits
an error but returns as handled continues unless it explicitly uses the internal
cancellation path. Likewise, no promise that MCL stops on an assembler's errors.
This is the principal semantic limitation requiring explicit maintainer assent.

Preserve buffered-input compatibility: `UB_RLCTRL` warm-aborts only when its
line is empty; otherwise it stores character 3. Do not turn that latter case,
or raw input delivered to an application, into a new system-level abort.

Between segments, check for operator Ctrl-C using the existing console input
discipline; preserve other typed-ahead characters and XSUB input ownership.
Do not steal arbitrary program input or flush the keyboard to implement this.
There is no new command keyword for cancellation in 1.3.

## SUBMIT/XSUB ordering

Recommend acquisition order: existing one-shot cold startup, then an available
SUBMIT record, then pending MCL, then interactive editor. Startup remains
one-shot through its existing cold marker. This preserves `CCP_READLN`'s current
SUBMIT-before-interactive priority and requires only one inserted MCL source.

Example: `SUBMIT JOB;DIR` runs JOB's submitted commands before the queued DIR.
If a submitted command starts another SUBMIT stream, existing stream behavior
governs; MCL stays parked until no submitted record remains. It is not a batch
stack and does not copy submitted records into its 128-byte object.

Submitted semicolons retain existing literal meaning. XSUB/BATCHIO continues to
supply transient program input through its current mechanism; MCL never becomes
that input. Normal stream exhaustion leaves a parked MCL remainder intact.
A recognized submitted-command error or explicit cancellation discards the MCL
remainder as well as applying the existing SUBMIT cancellation rules, preventing
surprise queued work after a failed job. Ordinary recognized cancellation must
be distinguished from successful exhaustion; do not blindly hook every call to
`CS_CANCEL`. No changes to NDR resolver ownership or PATH lookup order.

## Variable substitution boundary

Split raw interactive MCL text first. Expand variables in the selected segment
immediately before existing CCP navigation/core/CPX/transient dispatch. Keep
pending text unexpanded so `VAR X=NEW;ECHO %X%` observes NEW in the second command.
Expanded semicolons and quotes are argument characters, never reparsed as MCL
syntax. This avoids accidental creation of commands from variable values.

Expansion is one pass, nonrecursive, case-insensitive for names, uses `%NAME%`
and `%%`, and rejects undefined names or output over 127 characters. An unmatched
`%` is a substitution error. A value containing `%OTHER%` remains literal after
insertion. Each selected segment is expanded independently; failure in a later
segment does not roll back earlier commands, but does discard the remaining
sequence. Any original line over 127 characters is rejected before splitting,
even if each individual segment would fit. No expansion of a program's input.

Apply command substitution consistently to individual submitted/startup commands
when VAR is enabled, without MCL splitting those sources. With VAR disabled,
preserve existing percent characters literally. Define/query/delete syntax and
name limits were subsequently settled by the approved [VAR review](1.3-VAR-REVIEW.md). The grammar is
`VAR`, `VAR NAME`, `VAR NAME=value`, `VAR /D NAME`, with an empty assigned value
distinct from deletion. This does not require a program environment interface.

## Focused review cases

- 127-character line, 125-character maximum pending remainder; 128 rejected.
- Leading/trailing/repeated separators; whitespace-only line; quoted semicolons;
  unmatched quotes; unchanged FCB and 0080h command-tail construction.
- RET, Function 0, JP 0000h, GO/JUMP and WBOOT reconstruction resume ordering.
- Known CCP/BDOS Ctrl-C, disk abort, unknown/load/expansion failures discard.
- Raw application-controlled abort limitation is demonstrated, not hidden.
- SUBMIT JOB followed by MCL tail, exhaustion versus cancellation, and XSUB
  transient input consumption while MCL remains parked.
- Variable changes between segments, inserted `;`, inserted `%`, undefined and
  overflow, and ordinary NDR/PATH-prefixed command dispatch.
- HISTORY records the original input once; cold clears state; corrupt payload
  cannot dispatch; disabling MCL preserves v1.2 parsing.

The maintainer approved the parser rules, ordinary-WBOOT resume with known-abort cancellation,
SUBMIT-first ordering, interactive-only splitting and split-before-expansion
boundary. No memory default changes follow from semantics approval: the PDS
proposal separately gates defaults on measured floor compliance.
