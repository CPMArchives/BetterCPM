# 1.3 protected-memory recovery

Baseline: v1.2 `a496016b8f6430bc96ced32b339629bd566425e1`.

Recover 12 bytes without shrinking history, either private stack, drive vectors
or any transfer buffer. Two local UB_SELECT error branches use JR instead of
JP (two bytes). Remove UB_RRES, an unreferenced two-byte placeholder. Pack the
14-byte command-result/PATH state against the extension boundary, consuming the
old three-byte tail. Shift extension services five bytes into their old tail.
Move the gateway and BDOS up twelve bytes, leaving every later platform region
unchanged. All internal modules must be rebuilt together.

Fresh component builds on canonical Model 4, cpmsim-fullram and model2-fullram
confirm the same baseline eight-byte gap and the same four common BDOS savings:

| Component | v1.2 bytes | Repacked bytes |
| --- | ---: | ---: |
| Gateway | 248 | 248 |
| BDOS, including private stack and command state | 3,451 | 3,447 |
| Extension services | 420 | 420 |
| Inter-component padding | 8 | 0 |

Model 4 protected span decreases from 7,935 to 7,923 bytes. Model II has its
existing larger disk service and different BIOS/table sizes; these are unchanged.

| Profile | Old raw COM | Repacked raw COM | Complete-record maximum |
| --- | ---: | ---: | ---: |
| cpmsim-fullram | 57,345 | 57,357 | 57,344 |
| model2-fullram | 57,345 | 57,357 | 57,344 |
| Model 4 | 54,273 | 54,285 | 54,272 |

This creates twelve raw bytes for PDS v2 metadata. Spending those twelve bytes
returns each default raw ceiling to its v1.2 value, preserving the floors.
There is no budget here for additional permanently resident initialization or
allocation code. Composition and validation must use reconstructible code.
MCL and VAR therefore remain disabled in the default profile.

## Focused validation

- Fresh Model 4, checked cpmsim and Model II component builds fit all slots.
- `test_unified_bdos.py` passes selection/error branches, filesystem context,
  directory/allocation/extent/record operations and private stack checks. Its
  observed private-stack high-water remains 26 of 40 bytes.
- `test_ccp.py`, `test_history_wboot.py` and `test_history_lifecycle.py` pass.
- `test_pds_memory_boundary.py` executes the emitted protected COM reader for
  each platform with controlled disk records: 57,344 / 54,272 bytes accepted,
  the next 128-byte record rejected, and gateway/PDS canaries preserved.

The boundary fixture tests real assembled reader instructions, with disk calls
replaced by deterministic record delivery. It does not claim a native full-system
boot or replace the subsequent PDS/CONFIG lifecycle tests. Fresh build logs and
profile workspaces are in `build/review-1.3/memory/`.
