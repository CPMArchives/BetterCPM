# Boot-fixed RSX helper window

This prerequisite to PDS 2.0 implements the maintainer-approved private helper
rebasing direction. It allocates no additional protected RAM and does not move
NDR data into PDS. The public BRSX service and transaction interfaces remain.

The execution window is one KiB immediately below the persistent-data boundary.
The existing extension CALL and stack operands are named private placement words
(`RX_BASE`, `RX_CALL`, `RX_STACK`), with assembly assertions fixing their offsets.
Initially they describe the default history boundary. The later PDS cold worker
can update them once per cold boot; warm reconstruction does not resize anything.

Raw Model 4 entry and resolver images have a bounded position-independent
prologue plus a 128-byte typed relocation bitmap. After fixing the body, the
prologue replaces itself with a direct JP, so subsequent service calls cannot
apply relocation twice. Both images fit the existing one-KiB slots (990 and
962 bytes in the canonical build). The selector fits its existing tail.

The staged cache worker verifies each pristine 1024-byte helper image with
CRC16 before applying its source-derived bitmap. The nine rebased helper maps
are checked against independently assembled alternate origins, including page
carries. Fixed-CFG helpers have no window fixups. Slot identity/checksum admission
still precedes use; no source/profile pointer is published by a failed read or
failed fixup. Resolver prefetch still precedes the infallible memory commit.

The existing cache file grows from 2560 to 4096 bytes to carry these concrete
maps and code. Its page-aligned caller-owned staging reservation grows by 1536
bytes, separate from the existing manager transaction scratch band. Bounds are
checked before loading. This is transient transaction RAM, not PDS or permanent
resident storage. Private pack slots remain 1024 bytes and R3PACK's layout does
not change. Default unloaded and active-RSX TPA costs are unchanged.

## Focused evidence

- All helper fixups execute at default, negative and positive window offsets;
  corrupt images are rejected before staged writes.
- The raw resolver executes at each window and rebases exactly once.
- The production transaction engine passes retained/offline state reconstruction,
  overlapping live movement, unload recovery, namespace reclamation and 29
  returning disk-error cases. Scratch relocation across page carries passes.
- The checked staging test covers destructive CFG reads, helper read failures,
  CRC rejection and caller/context restoration.
- Later PDS integration adds NDR tests across the composed owner profiles and
  native platform boot/CONFIG tests; these are not claimed by this prerequisite.

Source-derived maps are private build artifacts, not a general third-party
allocator or public relocation API. The subsequent RAM PDS foundation classifies
its cold-written call operands explicitly for future ROM trampoline work.
