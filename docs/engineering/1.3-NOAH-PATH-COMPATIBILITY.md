# NOAH PATH compatibility repair proposed for 1.3

This is a narrow exception proposed for maintainer review to the locked NOAH
1.0 (021) identity. Published 1.2/021 artifacts and their accepted baselines are
unchanged. Do not publish a replacement under the 021 identity. The proposed
matching pair is NOAH 1.0 (022), preserving the existing command/archive/overlay
interfaces and changing only the generated protected-PATH bindings and revision.

## Demonstrated conflict

The merged PDS foundation reclaimed protected padding. The numeric PATH count
and six DU pairs now begin at `LY_EXT-13` (`LY_LERR+1`), rather than the old
`LY_EXT-16`. The BM1 descriptor's absolute location also moved with LY_SYS.
WBOOT entry addresses did not move. Consumers with baked layout bindings must
therefore be rebuilt together with the 1.3 kernel; matching WBOOT alone does
not prove that an older binding is still valid.

| Target | 1.3 WBOOT | 1.3 BM1 | 1.3 numeric PATH |
| --- | --- | --- | --- |
| Model 4 | E994h | D650h | E432h |
| cpmsim | F594h | E250h | F032h |
| Model II | F5ECh | E250h | F032h |

The current NOAH producer already derives WBOOT/BM1 from the selected layouts,
but still subtracts 16 for PATH. On a real production NOAH execution fixture,
a matching overlay placed only in the active C4: PATH entry is not found from
B7:. It prints `NOAH.OVL not found; operation stopped.` Local overlay placement
can hide this failure. The old regression also asserted the pre-PDS layout and
therefore could not qualify the merged kernel.

The repair changes the host-generated PATH address to LY_EXT-13 and replaces
the stale independent fixtures with the three literal bindings above. There
is no new resident code, PDS owner, public environment API or altered lookup
order. Invocation directory remains first, then the effective PATH; the first
found incompatible overlay still stops the search. Drive/user/DMA restoration
and Open scratch reset remain mandatory.

## Focused evidence

`python3 tools/test_noah_path.py` executes the production controller/overlay on
the Z80 core with an exact-DU BDOS provider. All 36 overlay PATH cases pass on
the three 1.3 layouts, including local precedence, cross-DU lookup, missing
files, malformed/foreign overlays, failed I/O, symbolic entries, absent/bad
descriptors, and query paths that need neither PATH nor an overlay. This is
focused component evidence, not full archive/codec or final Utilities-media
qualification.

Observed candidate pair from that test:

| File | Bytes | SHA-256 |
| --- | ---: | --- |
| NOAH.COM | 18862 | b6c972077293406d7d4e941c30172c2316dd8733e049424fcde3cfa53e62512a |
| NOAH.OVL | 36736 | 0031d48bc23eaeab53915c77fe49563d9ac96c2575b1cb93fe667e381a76cbb6 |

The controller and overlay are transient utility storage, not additions to
the OS resident footprint. Default unloaded TPA floors are unaffected.

Install and qualify the two files as a matching pair in the eventual 1.3
Companion Utilities package. Retain the earlier 021 archive/codec qualification
where functional inputs are unchanged, and record final pair/media hashes.
The revision exception and final package remain maintainer review gates;
this proposal does not mark 022 qualified or authorize merging/publication.
