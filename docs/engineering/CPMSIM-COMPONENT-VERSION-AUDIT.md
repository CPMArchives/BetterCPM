# cpmsim component version audit

Date: 24 October 2026.

## Source scope and decisions

Frozen core 1.0 is commit `3b2d2d7f4fe0472438465165f11fb550d79c8662`.
The integrated cpmsim implementation examined here is main commit
`24d525fea3ddea728249e6e41597052fb4e736ec`, including PR 483. Metadata-only
commit `d8fdf6abc0746d10ccd453d1b5fcbb6822a2ca1f` corrected core banners;
it did not assign the new component versions. This change records those
assignments. The complete Git commit containing it identifies the source for
rebuilding the newly labelled components; it is not a new binary acceptance
record.

| Component | Frozen implementation / API | Current implementation / API | Reason |
| --- | --- | --- | --- |
| BDOS | 1.9 / 1.2 | 1.9 / 1.2 | No BDOS service logic change; profile relocation and generated version strings alone do not advance its implementation. |
| BIOS | 1.13 / 1.7 | 1.14 / 1.7 | Checked reload, private checksum and identity services change implementation; public BIOS/disk calling contracts remain unchanged. |
| CCP | 1.4 / 1.0 | 2.0 / 2.0 | BCM2 carrier and replacement streaming command reload machinery change the command environment's on-disk contract. |
| CPX facility | 1.3 / 1.0 | 2.0 / 2.0 | Checked BCPX2 carrier, CRC and public/private binding change admission and module-format requirements. |
| RSX facility | 1.5 / 1.0 | 2.0 / 2.0 | BRSX3/BMET2 carrier admission, bound reconstruction packs and streaming reader change implementation and module-format requirements. |

The existing versioning policy includes externally visible binary formats in
the interface version. Checked loaders reject the old formats rather than
silently interpreting them as the new ones, so CCP, CPX and RSX receive major
interface and implementation increments. Keeping default-profile legacy
support does not make old carriers acceptable to checked profiles. Runtime
application and module entry conventions do not become incompatible merely
because these carrier contracts changed. Format schema numbers remain
independent identities: RSX API 2.0 uses BRSX3/BMET2, not a hypothetical BRSX2
format selected by its API number.

## Ownership evidence

- BDOS: `git diff 3b2d2d7 24d525f -- src/bdos` is empty. The generated
  `versions.inc` now changes to report other components' new identities; this
  is version-report data, not a change to BDOS service algorithms. Full-RAM
  profile relocation is generated by `tools/build_profiles.py` and
  `tools/system_layout.py`.
- BIOS: `src/bios/bios.mac` and the z80pack `biosplat.inc`, `disk.mac`,
  `checked-load.inc`, `checked-crc.inc` and `checked-identity.inc` implement
  profile-selected reload and integrity/identity services.
- CCP: `src/ccp` code is unchanged in this comparison, but its owning command
  environment includes the reload machinery in `src/system/command-stage1.mac`
  and `command-stage2.mac`. `tools/build_ccp.py` and `checked_carriers.py`
  generate BCM2 instead of BCM1 in checked profiles.
- CPX: `tools/build_cpx_module.py` and `checked_carriers.py` generate BCPX2;
  command stage 2 enforces its checksum, identity and streaming admission.
- RSX: `src/system/extens.mac`, the changed `r3*.mac` overlays and
  `tools/build_checked_resident_rsx.py` implement the protected entry and
  reconstruction changes. `build_rsx_module.py` and `checked_carriers.py`
  emit BRSX3/BMET2 with binding records.
- The ANSI host screen backend changes byte output to reduce stack use. This
  is module-specific work, not a BDOS logic change or a new generic BIOS API.
- Installation guards, package/export checks and build drivers also changed;
  they are not all charged to BDOS or treated as new public BDOS services.

These observations concern the integrated cpmsim work. They do not assert
that every unrelated utility change since the frozen commit belongs to it.
HELLO.RSX, HELLO.CPX and STATEFUL.RSX remain development fixtures.

## Aggregate and package identities

`metadata/core-1.0.json` preserves the frozen source/component combination.
The current subsystem matrix describes post-1.0 development. A new aggregate
core version has not been selected; in particular, these assignments do not
declare core 1.1. Existing core banners still show the last assigned milestone
pending that separate decision and cannot identify frozen membership.

Release package 1.0 remains in progress. Which core it will contain is
undecided. Its number does not constrain that core's number.

## Build identification and validation limits

Separate numerical subsystem build counters are not introduced. Exact source
revision plus target/profile identifies a source build; toolchain/options and
binary checksums identify actual qualified artifacts. Existing utility build
counters for CPX.COM and RSX.COM advance because their facility version strings
change; utility versions remain 1.0.

The earlier cpmsim qualification records retain their original source IDs,
version labels and checksums. Changing source/metadata changes the private
compatibility ID, so prepared checked workspaces must be generated afresh.
This version correction does not relabel those old artifacts or claim a new
full distribution, live emulator or physical Model 4 qualification.

Validation performed for this correction:

- Current matrix and generated includes agree; the regression checks the
  frozen manifest's commit, tree and all five historical component versions.
- CPX.COM and RSX.COM assemble, and executing their `/V` entries in the Z80
  harness prints API/implementation 2.0.
- Default cpmsim resident assembly fits; its emitted version-1 descriptor has
  three entries: CCP 2.0/API 2.0, BDOS 1.9/API 1.2, BIOS 1.14/API 1.7.
- A fresh full-RAM checked workspace builds resident services, all internal
  reconstruction slots, the pack, and command stages. Its compatibility ID is
  `cc7eb61ae61c154344337e272563b80f`.
- Command-stage CPU qualification passes 21 first-stage and 42 streaming
  admission cases. Rebuilding with the historical reference ID reproduces all
  four command-stage reference artifacts exactly.
- The shared version-query stack campaign passes at 24/32 bytes, with eight
  bytes reserve. The live Model 4 manager workflow tests have updated output
  expectations but were not rerun.
