# Optional 1.3 multiple command lines

This stage implements the approved MCL semantics and the subsequently approved
existing-byte abort latch. It follows the merged PDS/HISTORY/CONFIG foundation
at `9e0f907d`. MCL remains off by default. VAR execution and FLOW are not part
of this change, and no public environment or allocation API is added.

## Command behavior

When enabled at cold boot, MCL splits interactive input at semicolons outside
ASCII double quotes. It validates the whole accepted line before dispatching
its first segment. Quotes and argument spelling remain intact; single quotes
and backslashes acquire no new escape rules. Empty/space-only segments are
skipped. Selected segments retain existing CCP whitespace/tail processing.
The original editor line is recorded once in HISTORY; extracted segments are
not additional history records.

The existing 127-character editor limit remains. The owner stores only an
unexecuted remainder: length at +0 (1–125), state 1 at +1, raw text at +2 and
zero unused bytes through +127. Empty is all zero. Updates withdraw state
publication first, make bounded copies without console/disk calls, then publish
state 1 last. Pending payloads are checked for state, length, printable text,
balanced quotes and zero padding before any text is dispatched. Bad payloads
are cleared with `MCL invalid.`; changed immutable PDS metadata stops acquisition
with the cold-boot-required diagnostic.

Acquisition remains startup, available SUBMIT record, pending MCL, interactive
editor. Startup and submitted records keep literal semicolons/quotes; they are
not MCL input. Successful SUBMIT exhaustion leaves a parked remainder intact.
Recognized command/stream failures and explicit cancellation discard it.
XSUB/BATCHIO still owns submitted program input, and normal typed-ahead console
characters retain their order through the existing BDOS pending-input path.

Ordinary transient RET, Function 0, JP 0, BIOS WBOOT, GO/JUMP and handled core/CPX
returns continue the sequence. Known CCP syntax/lookup/load errors cancel it.
An application or CPX that prints an error and returns normally still continues:
no universal exit-status protocol is invented. Raw application Ctrl-C followed
by its own normal exit is likewise indistinguishable from ordinary completion.

## Approved cancellation and resident cost

Seven production BDOS abort sites now jump to an eight-byte stub which sets
bit 2 of existing private `CPTFLAGS` at SYS+95h and enters the original BIOS
warm path. Startup/composition bits remain intact. The Function-0 dispatch
table is unchanged. After warm reconstruction validates the PDS directory, it
clears only the enabled MCL owner and consumes the latch before command
acquisition. Cold boot already resets the flags and owner storage.

The cooked-input/output checks, pause paths, empty buffered-line Ctrl-C,
disk-error Ctrl-C and nonreturning read-only-disk abort retain their existing
control flow. Disk-error abort still clears the failed dirty-directory flag.
Nonempty buffered-line character 3 and raw input keep their existing semantics.
CCP failures use a transparent, validated transient cancellation entry.

Eight BDOS bytes pay for the stub:

| Recovery | Bytes |
| --- | ---: |
| Remove an entry load overwritten before use | 1 |
| Place the ordinary input getter at direct input's fall-through | 2 |
| Remove a redundant zero high byte in byte-block lookup | 2 |
| Remove a redundant zero high byte in extent conversion | 2 |
| Use a range-checked local branch for reset failure | 1 |

BDOS remains **3447 bytes**. Resident bases, stack sizes, state addresses and
default PDS allocations do not move. No TPA policy exception is taken.

## Reconstructed code and GET/POKE lifetime

The fixed boot worker lives in finished-program memory at 1700h. It cannot
remain the running parser: GET and POKE may overwrite that area while the CCP
continues without WBOOT. Instead, binding copies the 436-byte MCL code/template
into a 455-byte write-before-read area inside the CCP allocation. The remaining
19 bytes are its count/owner pointers, validated-header snapshot and parsing
scratch, all belonging to the same reconstructed command-code lifetime.

The existing instruction-fixup loop binds 34 source-derived internal word
offsets and 17 CCP call operands. Alternate assemblies, including an independent
page-carry check, verify those fixups. This is private static code binding, not
a new public module format, heap or third-party relocation/allocation service.
Each runtime operation compares the immutable directory with its fully
validated reconstruction-time snapshot before using the cached owner address.

GET/POKE protect the enlarged CCP allocation, preserving their ordinary flat
data area. COM execution can reclaim and overwrite the entire command
environment; normal reconstruction restores the helper before queued dispatch.
Queued GET/POKE/SAVE and full-TPA COM cases exercise both lifetimes explicitly.

## Private carriers and exact footprint

The raw worker expands into the adjacent formerly unused system-track slot:
10752–12799, with its gateway only at the final three bytes. SYSBUILD and host
packagers agree on that two-KiB carrier. No new required filesystem file is
introduced. Moving the 13-byte packed command-sector table into the worker
makes room for a second two-sector fetch in the Model 4 reloader, which shrinks
from 932 to **928 bytes**. Raw warm reconstruction reads two additional sectors.

Checked stages keep their existing 1024/2048-byte carriers, authentication and
disk placement; the embedded worker split moves to byte 864. The loader's
temporary-area floor is 1E00h on all profiles so command carriers cannot
overwrite executing reconstruction code. Every internal artifact must be
rebuilt/bound together.

| Item | Foundation | MCL stage |
| --- | ---: | ---: |
| Canonical worker payload | 1021 | 1591 |
| Checked Model II first/second stage payloads | 835 / 1544 | 931 / 2018 |
| CCP executable payload | 5522 | 5598 |
| CCP relocation entries | 504 | 496 |
| Raw / checked CCP carrier bytes | 6546 / 6568 | 6622 / 6644 |
| Reclaimable CCP allocation | 6144 | 6656 |
| Default HISTORY / MCL / VAR bytes | 192 / 0 / 0 | 192 / 0 / 0 |
| Default metadata / total PDS | 12 / 204 | 12 / 204 |

The 512-byte CCP allocation increase reduces free command-phase space, including
the area GET/POKE may safely edit. It is reclaimed for COM execution. Default
maximum complete-record COM capacity remains **57344** on cpmsim/Model II and
**54272** on Model 4. Enabling MCL alone adds 128 PDS bytes, making total PDS 332
and maximum COM **57216 / 54144**, respectively. CONFIG previews and STAT MEM
report those costs. HISTORY and VAR capacity choices retain their existing costs.

## Focused validation

`test_mcl.py` executes parsing/publication, maximum lengths, malformed payloads,
disabled legacy parsing, all history capacities, immutable-metadata failure,
warm/abort lifetime and runtime independence from the finished-program worker.
`test_mcl_abort.py` executes all seven production abort sites and distinguishes
ordinary Function 0. Existing BDOS, CCP, PDS/HISTORY and ownership-map checks
remain focused regressions.

`test_model2_mcl.py` uses emitted checked resident/CCP code on the z80pack CPU
core with controlled physical transfers: history once, quoting, returns,
GO/JUMP, full-fit/overflow, handled application errors, GET/POKE/SAVE, known
syntax/lookup errors, SUBMIT/XSUB ordering/input, NDR/PATH, typed-ahead input and
cooked versus raw Ctrl-C. `test_model4_mcl.py` checks native raw-media startup,
sequencing, returns, errors, exact optional full-TPA return/overflow and accounting.
Production-reader boundary checks cover all three platform default floors.

These are focused component/system checks, not a broad CP/M qualification
campaign or a completed 1.3 release. PR merging remains a maintainer action.
