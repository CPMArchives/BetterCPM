# 1.3 PDS / HISTORY / CONFIG foundation

This review stage follows the twelve-byte memory recovery (#683) and approved
private RSX window rebasing (#684). It implements the approved PDS ABI without
adding permanent allocation/composition code. MCL and VAR execution follow in
separate stages; their storage remains off by default.

## Composition and lifetime

The twelve-byte `PD`, ABI 2 directory is at `LY_SYS-12`. H/M/V length words and
a six-word zero-sum checksum determine contiguous owner storage below it.
HISTORY choices are 0/128/192/384, MCL 0/128, VAR 0/128/256/512 bytes. No gaps,
heap, callable allocation service, live resize or third-party registry exists.
BM1 keeps its version and offsets; +8 describes the live RSX boundary, +16 the
exclusive load ceiling. STAT derives PDS independently from its own directory.

The 1021-byte transient worker runs at 1700h before reconstruction. On cold
boot it validates saved BCST settings, clears owner storage, publishes the
directory, fixes the private RSX window, installs the three-byte gateway and
marks composition complete. Invalid saved settings select defaults with a
notice. Warm entry validates live metadata without reading saved settings or
recomposing; invalid live metadata requires a cold boot. HISTORY's BH/v1
packed span is checked, with isolated reset on corruption. Other subsystem
state, especially NDR and BATCHIO, remains outside PDS.

BCST version 2 retains the 256-byte protected record and 126-byte startup
capacity. Bytes 142–149 encode `CE`, version 1, H/M/V choice indices and two
zero bytes. BCST1 remains readable and selects default PDS. No live migration
is needed. Startup command edits and PDS edits preserve one another; existing
save verification and rollback remain in charge of persistence.

Model 4 fetches the worker from the previously unused 10752-byte system-track
slot. Checked loaders carry it across their existing two stages. Private
compatibility bindings include the new source inputs. All internal components
must be rebuilt together; older binaries with hard-coded history addresses
are not compatible with optional compositions.

## CONFIG and accounting

CONFIG's Command Environment/PDS domain shows active allocation bytes, saved
choices, pending choices and the next-cold-boot maximum COM capacity. Saving
does not change active composition. MCL/VAR entries reserve storage only in
this foundation; the screen states that command support follows later.

CONFIG's existing code/stack boundary is preserved with one concrete matching
`PDSCONF.OVL` companion, loaded from A:user 0 into its existing 9000h work area.
CRC32 binds its immutable 1792-byte portion; mutable session fields occupy the
remaining area of the 2048-byte carrier. Missing/mismatched files stop that
settings operation with a restore message. Distribution builders include the
companion. This is not a general overlay framework or a higher minimum TPA.

STAT MEM reports total PDS bytes, metadata, each owner and the actual current
maximum loadable COM, including the effect of installed RSXs.

## Exact memory cost

The default is H192/M0/V0 plus 12 metadata bytes, total 204. Recovered padding
and BDOS bytes pay for the directory. Default raw COM capacities return to
their v1.2 values; none of the policy floors is revised.

| Cold composition | PDS bytes | cpmsim / Model II maximum COM | Model 4 maximum COM |
| --- | ---: | ---: | ---: |
| Default H192/M0/V0 | 204 | 57,344 | 54,272 |
| H192/M128/V0 | 332 | 57,216 | 54,144 |
| H192/M128/V128 | 460 | 57,088 | 54,016 |
| Largest H384/M128/V512 | 1,036 | 56,448 | 53,376 |

Default raw capacities are 57,345 and 54,273 bytes, respectively. The COM
loader accepts complete 128-byte records. Model 4's protected span remains
7935 bytes: gateway 248, BDOS 3447, extension 420, disk 942, BIOS 756, file
loader 145, tables 576, history 192, PDS directory 12, dynamic gateway 3,
RSX table 41 and transfer buffers 1152, with one padding byte. Checked cpmsim
BIOS uses its existing 757-byte slot. Model II retains its larger disk/BIOS
layout. No new permanent code allocation is introduced.

The CCP grows from 5874 to 5904 executable bytes; its reconstructible rounded
allocation grows from 5888 to 6144. This is reclaimed on transient load and
does not reduce the unloaded COM floor. Private RSX cache staging grows by
1536 transient bytes as documented in the prerequisite; the manager remains
one KiB and default installed-RSX charges are unchanged.

## Focused verification

Use `test_pds_lifecycle.py`, `test_pds_descriptor.py`, `test_ccp.py`,
`test_history_lifecycle.py`, `test_history_wboot.py`, `test_pds_history_owners.py`,
`test_ndr_manager.py`,
`test_private_rsx_rebase.py`, `test_rsx_disk_cache.py` and
`test_rsx_checked_cache_stage.py`. These cover cold/warm composition,
corruption, exact owner bounds, HISTORY, expanded-layout NDR preservation,
offline reconstruction and staged failure handling.

`test_pds_memory_boundary.py` executes each platform's production reader with
controlled records: the policy maximum fits, the next record is rejected,
and gateway/PDS canaries remain intact. This is instruction-level evidence,
not a broad native qualification claim. Fresh profile builds are under
`build/review-1.3/final-profiles/`; Model 4 builds and focused native captures are
under `build/review-1.3/` and `build/test-results/config-pds/`.

Native CONFIG tests cover verified pending saves, startup preservation,
saved-layout cold activation, warm non-resize and STAT allocation accounting.
Existing startup and CRC/rollback inspection regressions pass.
`test_model2_pds_foundation.py` also boots the emitted resident/checked CCP,
executes exact-fit and overflow COMs, submits a full-TPA command then VER,
loads/unloads NDR, reenters CONFIG after WBOOT and exercises XSUB
Function-10 input with matching test carriers on scratch media. Only physical disk transfer
is replaced in this Model II CPU fixture.
MCL/VAR parser/dispatch tests belong to their later implementation stages.
No PR is to be merged without maintainer review.
