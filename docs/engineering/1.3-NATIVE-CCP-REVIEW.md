# Native packed-CCP reconstruction boundary

Status: concrete review proposal, not an implemented native rebuild repair.
Baseline: merged 1.3 feature source at `bcd27a0a` (PR #687). No runtime,
resident-memory, PDS-default or TPA-policy changes are made here.

`tools/build_native_ccp.py` already expands prepared inputs and compares the
native inner CCP with `ccp.bin`. That source-assembly parity path is distinct
from producing the new packed boot carrier. RLMBUILD and the native Source Disk
still assume that those two layers are the same image.

## Measured conflict

`python3 tools/build_ccp.py` followed by
`python3 tools/measure_native_ccp_gap.py` reports:

| Item | Current value |
| --- | ---: |
| Inner image / record-aligned file | 8470 / 8576 bytes |
| Packed outer payload | 6014 bytes |
| Outer allocation / fixups | 14848 bytes / 50 |
| Outer header / raw module | 512 / 6526 bytes |
| Legacy native input stride | 5632 bytes |
| Inner / outer aligned input-slot overlap | 2944 / 384 bytes |
| Legacy 1024-byte header plus outer payload | 7038 bytes |
| Fixed raw carrier capacity | 6656 bytes |

`build_disk_utilities.py` currently generates size/allocation from the inner
image but relocation count from the outer module. The inner image has 686
fixups, while the configured native scan expects 50. `rlmbuild.mac` loads all
three input images into overlapping fixed slots and always writes an eight-
record/two-sector header. Merely selecting packed inputs does not repair the
slots or the header; merely enlarging slots does not perform native packing.
Simply enlarging the disk carrier would cross the filesystem boundary.

The native Source Disk currently emits three full inner CCP assembly variants.
They cannot be treated as three packed bootstrap links. Do not silently feed
one layer to metadata describing the other or claim complete native rebuilding
because the inner assembler comparison passes.

## Recommended bounded 1.3 direction

Prepare three explicit packed-bootstrap assembly inputs from the host producer,
at BB00h/BC01h/BD37h. Retain the complete inner source separately. Native ZSM4/
LINK can assemble these prepared inputs and RLMBUILD can construct a logically
byte-identical ordinary carrier. Use consistent outer size/allocation/fixup
metadata, 6144-byte slots and the actual one-sector header. Keep legacy two-
sector support for ordinary inputs that require it. Slots at 4000h/5800h/7000h
and a 1024-byte header area at 8800h end at 8C00h, below the established floors.
Reject unsupported size/count combinations before loading any input.

Require focused production-RLMBUILD tests for exact output, CP/M tail padding,
wrong/truncated/extra inputs, relocation scan/overflow and insufficient active
TPA. Verify the three prepared native assembly variants against host bytes,
plus existing inner native/cross parity where the native toolchain is available.
No general compressor, new runtime format, resident service or PDS machinery
is required by this direction.

**Capability decision:** this preserves native assembly and module construction
from prepared release sources. Editing the inner CCP would require host
repacking before preparing those bootstrap inputs. A fully native private
packer would restore that edit/repack workflow but is additional implementation
work and should be explicitly chosen, rather than hidden in release cleanup.

The recommendation is proposed for maintainer review because the locked 1.3
scope preserves 1.2 functionality. Do not silently weaken that contract or
declare final Source/System acceptance while this boundary is unresolved.
SYSBUILD/SYSGEN of already matching exported artifacts is a separate path and
must remain intact. Historical source disks and released binaries are unchanged.
