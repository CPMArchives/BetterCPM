# Native packed-CCP reconstruction

Status: maintainer approved the prepared-input contract on 2026-11-21;
implemented for review in PR #690. Baseline: merged 1.3 feature source at
`bcd27a0a` (PR #687). No resident-memory, PDS-default or TPA-policy changes.

## Approved contract

The native build disk exports `CCP.MAC`, `CCPALT.MAC` and `CCPCHK.MAC` as
host-prepared packed-bootstrap assembly inputs at BB00h, BC01h and BD37h.
Native ZSM4/LINK assemble these inputs; RLMBUILD reconstructs the ordinary
carrier, including its relocation directory. Complete editable inner CCP source
remains in the source archive. Editing it requires host repacking and a matching
prepared build disk. There is no native compressor in 1.3. This capability
tradeoff was explicitly approved; it is described in the shipped build guide.

`build_native_ccp.py` separately retains native inner-source assembly parity.
SYSBUILD/SYSGEN composition and installation of matching artifacts are unchanged.
Historical source disks, published artifacts and accepted baselines are unchanged.

## Repair

| Item | Measured value |
| --- | ---: |
| Inner image / record-aligned file | 8470 / 8576 bytes |
| Packed outer payload | 6014 bytes |
| Outer allocation / fixups | 14848 bytes / 50 |
| Outer header / raw module | 512 / 6526 bytes |
| Repaired input stride | 6144 bytes |
| Input slots | 4000h / 5800h / 7000h |
| Header workspace / exclusive end | 8800h / 8C00h |
| Fixed raw carrier capacity | 6656 bytes |

The previous metadata mixed inner size/allocation with outer fixups. Legacy
5632-byte slots overlapped by 2944 bytes for inner inputs, or 384 even for packed
inputs. Its fixed 1024-byte header would produce a 7038-byte outer carrier,
exceeding the disk slot. The repair uses one coherent outer descriptor and its
actual header size, retaining two-sector support when the carrier fits.
Host preflight rejects unsupported lengths, headers, allocation and fixup tables
before utility production. Checked-profile native packaging remains explicitly
unavailable; its guarded COM is built with inert metadata, not a raw-carrier parse.

RLMBUILD admits workspace only when active TPA reaches 8C00h. Extra-record
probes use header scratch, so a full input never spills into the next slot.
After relocation discovery, it reconstructs and compares every alternate byte
before creating output; count agreement alone no longer accepts altered
constants. Input close errors are propagated. Output record padding handles
zero and one trailing byte without a zero-count LDIR. RLMBUILD advances from
1.0 (006) to 1.0 (007); no accepted baseline is promoted.

## Focused evidence

- Native ZSM4/LINK: all three prepared inputs reproduce 6014 host bytes each.
  Executed RLMBUILD from the exported build disk reproduces the 6526-byte raw
  carrier exactly, plus two zero padding bytes for CP/M records.
- Native editable inner CCP assembly still reproduces all 8470 host bytes.
- Production RLMBUILD instruction tests: 20 parity, missing/truncated/extra/
  mismatched input, file-service error, relocation-overflow, exact workspace,
  one/two-sector header, full-slot and zero/one-byte padding cases pass.
  Malformed descriptor preflights reject unsupported layouts.
- Existing native-builder admission/query regression: 22 cases pass with
  protected canaries intact; exact new RLMBUILD admission is 8C00h.
- Native build-disk inventory/readback, matching RESPACK map, generated includes
  and complete source-archive coverage pass.
- Production COM-reader boundary fixtures accept 57344 bytes on cpmsim/Model II
  and 54272 on Model 4, reject the next record and preserve protected canaries.
  Model 4 uses the fresh host build; cpmsim/Model II reuse the unchanged resident
  outputs from the focused #689 readiness build. This PR changes no resident
  source, carrier bytes or default PDS allocation.
