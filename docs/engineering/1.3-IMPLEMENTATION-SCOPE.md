# BetterCP/M 1.3 implementation scope and architecture review gate

Baseline: `a496016b8f6430bc96ced32b339629bd566425e1` (v1.2).
Status: authorized implementation program with approved PDS/MCL proposals and
private RSX rebasing. Foundation implementation is staged for review; this is
not a released 1.3 or a full qualification claim.

Maintainer-approved proposals:
[PDS ABI](1.3-PDS-ABI-PROPOSAL.md) and
[MCL semantics](1.3-MCL-SEMANTICS-PROPOSAL.md).
Private helper rebasing was also approved after the overlap finding; see
[RSX window](1.3-RSX-WINDOW.md).

## Locked release contract

- One cold-boot-composed PDS with explicit HISTORY, MCL and variable owners.
  Owner locations/capacities remain fixed until the next cold boot. No heap,
  allocation/free, fragmentation machinery, compaction or live resizing.
- HISTORY remains built in, with its existing observable behavior and default
  192-byte object (10 control bytes, 182 packed record bytes). HISTORY.RSX was
  an option, not a committed feature, and is not a planned direction.
- MCL remains independent of FLOW. Preserve 127-character input and provisionally
  allocate 128 persistent bytes for only the unexecuted remainder. No transient
  or reconstructed-command-environment pointers may persist.
- VAR provides case-insensitive session variables: `%NAME%`, literal `%%`,
  one-pass nonrecursive expansion. Undefined names and expansion over 127
  characters prevent dispatch. Warm reconstruction preserves variables; cold
  boot resets them. Startup values can be set through STARTUP/SUBMIT. No
  program-visible environment API. Cheap derived read-only values are optional
  and must not require additional PDS storage.
- CONFIG gains a Command Environment/PDS domain, retaining active/pending/saved
  semantics and verified persistence. Composition changes apply next cold boot.
- STAT MEM reports total PDS bytes, owner allocations and maximum loadable COM.
  A 64-cell visualization is optional later work.
- NDR and its table stay entirely in NDR.RSX. Other resident-private state stays
  with its subsystem, including BATCHIO and BIOS/disk state.
- Preserve CP/M command tails, NDR/PATH, SUBMIT/XSUB, TCAP, HELP, NOAH 1.0 (021)
  and other v1.2 behavior. No live history migration is needed on cold boot.
- FLOW moves to a later candidate, likely 1.4. VIEW, timestamps, ports,
  generalized command queues and unrelated cleanup are excluded.

## v1.2 baseline source findings (before this implementation)

`src/system/gateway.mac:SYS_COLD` invalidates the history signature;
`SYS_WARM` bypasses that store. Both reconstruct through `SYS_ENTER`.
The `BM` version-1 descriptor's offset 8 is labelled as the PDS lower boundary,
but RSX publication overwrites it with the installed RSX lower boundary.
It cannot serve as an immutable PDS locator when RSXs are present.
`src/system/layout.inc` fixes the PDS top at LY_SYS and gateway at LY_HIST-3.
CCP history uses absolute LY_HIST-derived addresses and a compile-time capacity.
`src/system/r3final.mac` also uses LY_HIST and the published PDS boundary.
These contracts must change together; adding a directory alone is insufficient.

`src/ccp/ccp.mac:CCP_READLN` currently gives A:$$$.SUB precedence before the
interactive editor. Submitted records are an existing disk queue, distinct
from program input. GO/JUMP push the BIOS warm-entry address as their return
target. The interactive Ctrl-C handler also uses the normal Function 0 path.
The approved MCL proposal supplies the explicit completion/abort state for its
subsequent stage; WBOOT alone must not be treated as success.

CONFIG has private pending startup state and separate pending-only/all-current
save paths. Its disk records must not be repurposed without a defined compatible
saved-format extension. Existing STAT tests deliberately reject BM version 2;
the new discovery contract must explicitly address existing descriptor users.

## Reproducible layout arithmetic (not runtime boundary tests)

Values derived from v1.2 `build_profiles.profile_inputs` and canonical layout:

| Profile | Gateway | PDS interval (end exclusive) | Raw COM space | Record-aligned COM |
| --- | --- | --- | ---: | ---: |
| cpmsim-fullram | E101h | E104h–E1C4h | 57,345 | 57,344 |
| model2-fullram | E101h | E104h–E1C4h | 57,345 | 57,344 |
| Model 4 canonical | D501h | D504h–D5C4h | 54,273 | 54,272 |

Each has one byte of load-record slack. Moving only the lower PDS boundary
down 128 bytes would reduce the cpmsim/Model II limit to 57,216 and Model 4 to
54,144. Adding 144 bytes would yield 57,088 and 54,016 respectively. These are
hypothetical costs, not selected layouts. Fresh builds on all three targets
subsequently measured eight padding bytes and recovered four BDOS bytes.
The [memory prerequisite](1.3-MEMORY-FOUNDATION.md) recovers twelve bytes; the
[foundation](1.3-PDS-FOUNDATION.md) spends them on the directory, preserving
both policy floors and default HISTORY. MCL and VAR remain off by default.

## Reviewed decisions and remaining stage boundaries

The approved PDS ABI uses a separate twelve-byte PD2 directory with fixed owner
lengths; BM1 retains its live RSX boundary. Saved BCST2 configuration composes
owners only at cold boot. The approved MCL proposal fixes splitting, abort and
source ordering independently from FLOW. Its VAR section fixes substitution timing. Detailed VAR grammar/name limits
remain a later stage review boundary.

The fixed RSX manager overlap was surfaced separately. The maintainer approved
rebasing private helpers below the actual PDS, preserving default memory costs.
No dependent architecture remains open for the PDS/HISTORY/CONFIG foundation.
If later source findings require a consequential architecture change, surface
that boundary for review before implementing it.

## Reviewable stages and focused evidence

1. PDS/HISTORY/CONFIG foundation: owner discovery and bounds validation;
   warm/cold lifetime; saved-layout cold boot; unchanged default history.
2. MCL: parser, ordering, reconstruction, cancellation and focused SUBMIT/XSUB
   interactions under the reviewed state machine.
3. VAR plus CONFIG/STAT integration: define/query/delete, undefined/overflow,
   one-pass expansion, warm/cold lifetime; NDR/PATH interactions and accounting.

For each stage report resident bytes, metadata and each owner allocation.
Run exact maximum-COM boundary tests on cpmsim, Model II and Model 4 before
finalizing defaults. Reuse focused existing regressions; no broad qualification
campaign. Reconcile stale HISTORY.RSX/FLOW roadmap statements while preserving
historical release records. Open stage PRs with rationale and test evidence;
do not merge without maintainer review.
