# VAR command, owner format and carrier review

Status: proposed for maintainer review, not implemented VAR support.
Baseline: merged main `29e2be07` (PR #686). VAR remains off by default.

The approved MCL design explicitly left define/query/delete syntax and name
limits for a separate VAR review. This document makes that decision concrete.
Source inspection also found a private carrier limit that must be resolved
before adding VAR to the CCP. No production code or on-disk format changes
are made by this review packet.

## Recommended command contract

| Input | Result |
| --- | --- |
| `VAR` | List stored names and values, sorted by name, as `NAME=value` |
| `VAR NAME` | Print that assignment; undefined is an error |
| `VAR NAME=value` | Define or replace; empty value is a defined empty string |
| `VAR /D NAME` | Delete exactly that name; undefined is an error |

Recommend names of 1–8 ASCII characters: first a letter or underscore,
remaining characters letters, digits or underscores. Match case-insensitively
and store uppercase names. Eight characters follow the project's familiar
command/file stem limit and bound name overhead in the small owner.

Skip spaces before the operation/name. For assignment, require `=` immediately
after the name. Preserve every character after the first `=` as the value,
including spaces, quotes and additional equals signs. For query/delete allow
only trailing spaces after the name. No quote stripping or new escape language.
Stored values are printable ASCII, including a literal percent sign, with a
format limit of 127 bytes; the existing whole command limit further constrains
values users can enter. There are no derived system variables in this stage.

`VAR` is a CCP command, available without RCP.CPX. Explicit transient prefixes
keep their existing bypass behavior. With VAR storage disabled, an unqualified
VAR command reports that CONFIG/cold boot is required. Other commands retain
literal percent handling when VAR is disabled. No environment API is exposed
to programs, and no separate VAR.COM is proposed.

## Recommended owner representation

Use the approved fixed VAR allocation of 0/128/256/512 bytes. Two bytes at +0
hold the little-endian used record-byte count, excluding those two bytes.
Records follow contiguously:

```
name length (1 byte), value length (1 byte), name bytes, value bytes
```

Names are unique, uppercase and sorted lexicographically. No terminators,
stored pointers, per-record versions, slots or capacity metadata. Unused bytes
are zero. An empty owner is entirely zero. The existing PD2 header supplies
capacity and discovery; its format does not change.

Validate bounds, complete records, name/value grammar, strict name ordering
and zero unused bytes before using the owner. Malformed data resets only VAR,
reports a diagnostic and rejects the selected command, cancelling pending MCL
and a submitted stream consistently with existing recognized command errors.
Invalid immutable PDS metadata retains the existing stop/cold-boot-required
policy; do not reinterpret it or guess owner addresses.

Construct edits in bounded reclaimable scratch before changing the owner.
Capacity/syntax failures leave the old table intact. Once validation and size
checks succeed, copy the complete replacement without BDOS/console/disk calls.
This is bounded editing inside one fixed owner, not PDS allocation, resizing
or general compaction. Scratch must live with reconstructed command code and
remain safe across GET/POKE, as the MCL lifetime finding requires.

Example capacity: a four-character name with a sixteen-character value costs
22 bytes per record, so the three enabled capacities hold 5/11/23 such records.
This is illustrative capacity arithmetic, not a promised fixed variable count.

## Already locked substitution and lifetime

Expand the selected command immediately before CN_NORMAL/core/CPX/transient
dispatch, after interactive MCL splitting and original-line history recording.
Apply the same expansion to individual STARTUP/SUBMIT commands without splitting
those sources. Pending MCL text remains unexpanded. `%NAME%` substitutes once;
`%%` produces one literal percent. Inserted values are not rescanned, and their
semicolons/quotes never create MCL syntax. Undefined, invalid or unmatched names
and output over 127 characters reject dispatch and cancel pending work.

Expansion also precedes VAR command parsing: `VAR COPY=%SOURCE%` copies the
current value; `VAR TEXT=%%SOURCE%%` stores literal `%SOURCE%`. A defined empty
value expands to zero characters and remains distinguishable from an undefined
name. Failure in a later MCL segment does not undo earlier completed commands.

Ordinary COM execution, Function 0 and WBOOT preserve the owner. True cold boot
zeros it. STARTUP/SUBMIT can establish initial values. Program console input,
including XSUB data, never passes through substitution. NDR remains NDR.RSX
state, and PATH order/semantics stay intact.

## Measured carrier boundary

Fresh `build_ccp.py` on the merged baseline produces:

| Item | Bytes |
| --- | ---: |
| CCP executable payload | 5598 |
| CCP full image / reclaimable allocation | 6435 / 6656 |
| Raw / checked command carrier | 6622 / 6644 |
| Fixed command carrier capacity | 6656 |
| Checked spare bytes | 12 |
| Canonical PDS worker | 1591 |
| Tightest checked worker budget / spare | 1598 / 7 |
| Checked Model II stage 1 / stage 2 spare | 1 / 6 |

The raw CCP occupies sectors 27–39. Sector 40 begins the filesystem with the
existing DPB OFF=2. Simply increasing COMMAND_SECTORS or the CCP carrier cap
would overwrite filesystem space and also require coordinated SYSBUILD changes.
Moving all VAR code into the existing private worker does not solve the checked
carrier limit, and leaving running code at 1700h would break GET/POKE.

Recommend a bounded private-carrier packing investigation before implementation,
keeping VAR code/scratch with the reconstructed CCP. Avoid a new always-resident
service or a new optional filesystem helper dependency. This requires explicit
review because all matching raw/checked readers and packagers must agree on the
private format. It is not authorized merely by this proposal.

`tools/measure_var_carrier.py` is a host-only sizing probe. A grouped-flag
LZ-style candidate with 4096-byte backward distance and lengths 3–18 reduces
the existing 5598-byte executable payload to **4356 bytes**, a gross saving of
**1242 bytes**, with a verified reference round trip. The payload SHA-256 is
`6d9958a46edd5d3bc60da5f5465ce2c331895448a3147b6b7665dced11eee7e2`.

This excludes a Z80 decoder, new format metadata, VAR code and its fixups. It
does not establish that the full feature fits or that a decoder executes safely.
Any candidate must authenticate checked packed bytes, enforce input/output and
backreference bounds, reconstruct at the existing safe placement, then relocate
the complete executable exactly as before. Decoder placement and stage budgets
remain implementation feasibility gates; stop again if they cannot be met.
No production compression format or decoder is introduced by this packet.

No resident bytes or default floor reduction is approved.

CCP allocation and command-phase GET/POKE cost before finalizing the change.
