# MCL integration: cancellation timing review

Status: historical review boundary, resolved by maintainer approval of the existing-byte abort latch. See [implemented design and measurements](1.3-MCL-IMPLEMENTATION.md). The investigation below records the decision context; its probe measurements predate the implementation.
Baseline: merged main `9e0f907dcc522b998233fddb93f07ffc1146322f`.
The approved parser, ordering, 128-byte owner format and default-off policy
remain unchanged. No production source or default memory layout changes in
this review packet.

## Measured constraints

Fresh canonical component assemblies reproduce these limits:

| Component | Used | Limit / remaining |
| --- | ---: | ---: |
| CCP executable payload | 5522 bytes | 88 carrier bytes remain with checked binding |
| CCP allocation | 6144 bytes | Reclaimed for COM execution |
| CCP relocations | 504 | 504; no spare entries |
| PDS transient worker | 1021 bytes | 1021-byte raw slot; full |
| Model 4 command reloader | 932 bytes | 932; full |
| Checked first stage | 833 bytes | 932; 99 spare |
| Checked second stage | 1542 bytes | 2024; 482 spare |

The checked stage numbers come from the matching foundation profile build.
The existing worker split can potentially grow by 581 bytes without enlarging
either checked carrier, provided its copy split is adjusted. That is a budget,
not a claim that the unimplemented MCL routines fit it.

The approved MCL proposal requests immediate clearing from known resident
abort paths, after validating PDS metadata and the owner location. A working
reference implementation using the production validator costs **184 resident
bytes**, including its 28-byte clear/disabled-owner body. Eight executed cases
verify correct owner clearing, disabled-owner no-op, corrupt-metadata no-op and
neighboring owner/directory canaries. This is a reference cost, not a lower
bound or proof that a smaller validator is impossible.

The transient worker cannot serve as a resident cancellation routine: a COM
can overwrite it before Ctrl-C or a disk abort occurs. MCL being off by default
does not remove code linked permanently into BDOS. Simply charging 184 more
protected bytes would lower default complete-record COM capacity to 57088 on
cpmsim/Model II and 54016 on Model 4. That violates the locked policy. No such
change has been made, and no safe recovery of 184 bytes has been established.

## Recommended amendment: defer the clear until reconstruction

Use bit 2 of the **existing** private `CPTFLAGS` byte at `LY_SYS+95h` as a
recognized-abort latch. Bits 0 and 1 retain their startup/composition meanings.
This introduces no new byte, PDS owner, allocation or public interface.

At existing BDOS abort sites, replace the current jump target with a common
eight-byte private routine:

```asm
        LD HL,LY_SYS+095H
        SET 2,(HL)
        JP LY_BIOS+3
```

The jumps remain three bytes each. The routine still needs eight recovered
resident bytes before integration; this amendment does not waive the floor or
claim that recovery has already been achieved. Four executed cases verify
that the latch preserves all combinations of the two existing flag bits.

After reconstructing executable worker code, validate the PDS directory,
clear the MCL owner if enabled, then consume the latch **before any queued
command can be selected**. Invalid live metadata follows the existing
cold-boot-required failure path. True cold boot already clears CPTFLAGS.
Ordinary Function 0, RET, JP 0000h and BIOS WBOOT do not set the latch, so
normal sequential continuation remains unchanged. Recognized CCP errors can
still clear MCL directly while its transient code is available.

Production sites include cooked input, output pause/check, empty buffered-line
Ctrl-C, disk-error Ctrl-C and the existing nonreturning read-only-disk abort.
Do not redirect the normal Function-0 table entry. Nonempty buffered-line
character 3 and raw application input keep their current behavior. Preserve
the existing dirty-directory handling before disk-error reconstruction.

This differs from the approved proposal's explicit immediate-clear/no-latch
mechanism. It therefore requires maintainer review, even though cancellation
still takes effect before the next command and uses no additional state byte.

## Transient code placement direction

Keep MCL parsing, owner validation and dequeue logic reconstructible, sharing
the existing private PDS worker and fixed entry conventions. Prefer extending
its raw carrier into the adjacent unused 11776-byte system-track slot rather
than adding a new required file or a loadable resident subsystem. The checked
worker remains split across the existing stage carriers within the measured
581-byte growth budget. No PDS ABI, owner payload or CP/M command-tail change.

The raw Model 4 reloader is full. Moving its 13-byte packed command-sector
table into the enlarged worker is a concrete way to make room for a second
two-sector fetch and six table bytes (nine added bytes against thirteen moved).
Both package builders and SYSBUILD must describe the enlarged private worker.
All layout-dependent internal artifacts must be rebuilt together.

Keep CCP hooks small and use fixed private worker entries/runtime-relative
offsets, as HISTORY binding already does, rather than enlarging the public
carrier header. Measure the final parser and hook costs before committing to
this placement. If they exceed the available private slots, return with exact
costs rather than silently adding a file, changing a public ABI or lowering TPA.

## Decision requested

Approve the existing-byte recognized-abort latch and deferred validated clear,
with the original parser/ordering semantics and unchanged memory floors.
Otherwise retain immediate resident clearing and investigate further resident
recovery; the measured reference currently costs 184 bytes. Neither option
authorizes a memory-policy exception or automatic PR merging.

## Reproduction

Build `build_bdos.py`, `build_ccp.py`, `build_bios.py` and `build_ccpreload.py`,
then run:

```text
python3 tools/measure_mcl_integration.py
```

For checked carrier budgets, supply `--checked-loader` with the matching
profile's `build/z80pack/command-loader/results.json`. The tool assembles and
executes cost probes, emits JSON and changes no production source. Its result
is an integration-cost experiment, not parser or full-system qualification.
