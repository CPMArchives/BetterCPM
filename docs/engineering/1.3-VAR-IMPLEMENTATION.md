# Optional VAR and packed CCP implementation

This implements the maintainer-approved [VAR review](1.3-VAR-REVIEW.md) on
merged MCL main `29e2be07`. VAR remains off by default. There is no resident
variable service, public environment API, new CPX dependency or live PDS resize.

## User behavior and state

`VAR` lists assignments in sorted order. `VAR NAME` queries one assignment,
`VAR NAME=value` defines/replaces it, and `VAR /D NAME` deletes it. Empty values
are defined strings, distinct from deletion. Undefined queries/deletes fail.
Names have 1–8 characters, begin with a letter/underscore and continue with
letters/digits/underscores; matching ignores case and stored names are uppercase.
Assignment requires `=` immediately after the name. Every character following
it belongs to the value, including spaces, quotes and additional equals signs.
Values are printable ASCII. No quote stripping or additional escaping is added.

The CCP handles VAR before CPX dispatch, including when RCP is absent. Explicit
transient prefixes retain their bypass. With storage disabled, VAR explains
that CONFIG and cold boot are required; other commands keep literal percent
characters. CONFIG F/C retains Off/128/256/512 choices, saved for the next cold
boot. STAT MEM retains explicit owner and maximum-COM accounting.

Expansion occurs once per selected command, after interactive MCL splitting
and history insertion, before named-directory normalization, navigation and
core/CPX/transient dispatch. It also applies to STARTUP/SUBMIT commands, whose
semicolons remain literal. Pending MCL text stays unexpanded, so later commands
observe preceding assignments. Program input, including XSUB records, bypasses
expansion. `%NAME%` inserts a value, `%%` inserts one percent, and inserted
percent signs/semicolons/quotes are never rescanned. Undefined/invalid/unmatched
names and results over 127 characters prevent dispatch and cancel pending MCL
and submitted work. Earlier completed segments are not rolled back.

Examples: `VAR COPY=%SOURCE%` copies a current value; `VAR TEXT=%%SOURCE%%`
stores literal `%SOURCE%`. Expansion may produce an empty command. The original
interactive line, including substitutions, is recorded once in history.

VAR's fixed owner begins with a two-byte used record-byte count, followed by
`name length, value length, name, value` records. Names are unique, uppercase
and sorted; unused allocation bytes are zero. Off has no object. The PD2
directory and allocation choices do not change. The two control bytes are
inside the configured owner allocation, not additional global metadata.

Every enabled command checks owner bounds, complete records, canonical names,
strict sort order, printable values and zero padding. Corrupt payload resets
only VAR and rejects the command; changed immutable PDS metadata stops with
the existing cold-boot-required policy. Updates construct a complete replacement
in bounded 512-byte CCP scratch. Syntax/capacity failure preserves the old
table. The successful bounded copy performs no BDOS/console/disk calls.

The owner survives COM execution/WBOOT and resets at true cold composition.
STARTUP/SUBMIT can establish startup values. No derived system variables are
added. NDR remains owned by NDR.RSX, and PATH lookup order is unchanged.

## Private carrier packing and reconstruction

The merged checked CCP had only 12 spare carrier bytes. This stage keeps the
13-sector raw command slot and filesystem start intact. Matching raw/checked
CCP carriers now use the existing header's one-sector size rather than two;
the checked header normalization constant is correspondingly 512. The raw
reader also retains two-sector RLMBUILD compatibility, while rejecting other
header sizes and retaining strict CPX class checks. Other loader
placement, relocation admission, CRC and binding rules remain unchanged. CPX
and RSX formats do not change. Rebuild matching private artifacts together.

The ordinary carrier now contains a small CCP bootstrap and compressed canonical
command code/internal fixups. Its ordinary relocation table has 50 entries and
fits the one-sector header. Checked admission authenticates the complete carrier
before entry, including the packed bytes. Raw media retain their existing
unauthenticated private-carrier contract.

Packing uses grouped literal flags, one-byte short references (length 2,
distance 1–128), and two-byte long references (length 3–18, distance 1–2048).
The host chooses a minimum-byte parse for that grammar. Internal fixups are
sorted deltas: one byte for 2–255, otherwise zero plus a 16-bit delta. This is
a bounded private executable representation, not a public compression/module
service or a general overlay framework.

The reader initially reserves 14848 bytes. The 6008-byte packed executable runs
below its decoded destination at offset 6144. It enforces packed-input bounds,
output bounds, valid backward references and complete input consumption. The
fixup decoder enforces table bounds, nonoverlapping increasing offsets and
targets wholly inside executable bytes. It relocates the reconstructed CCP,
publishes its higher base and 8704-byte allocation, then enters it. No command
can dispatch before successful reconstruction. Failed decoding stops with a
cold-boot-required diagnostic.

The lower 6144-byte bootstrap area is then finished-program memory, available
to GET/POKE and COM loading. Only the complete inner CCP remains protected.
VAR code/cache/scratch and the existing MCL runtime therefore survive ordinary
GET/POKE operations; COM execution reclaims the whole command environment and
normal WBOOT reconstructs it. No pointers into bootstrap memory persist.

The standing command-phase cost increases by **2048 bytes**. GET/POKE's safe
data area shrinks by that amount; the bootstrap's temporary area is released
before commands run. All command code remains reclaimable for COM execution.
No new permanently resident bytes are allocated and no default-floor exception
is taken. The private worker/carrier budgets remain at the merged MCL sizes;
the checked reader constants do not increase its code length. The raw reloader
grows from 928 to its exact 932-byte limit: explicit legacy header/class
validation is paid partly by a six-byte loop-counter simplification. The

## Focused evidence

`test_command_packing.py` checks host literal/short/long/overlapping streams and
executes the emitted Z80 bootstrap at three independent runtime bases. It checks
exact decoded code/fixups, allocation publication, protected canaries and invalid
backreference, truncation, output-overrun and relocation-table bounds. Checked
reader admission tests retain independent corruption/identity/boundary fixtures
(21 first-stage and 42 streaming cases). `test_raw_command_headers.py` checks
one/two-sector raw CCP admission, invalid sizes and CPX class rejection.

`test_var.py` executes owner validation, sorted list/query/define/replace/delete,
empty values, invalid names/values, atomic capacity/error behavior, one-pass and
literal-percent expansion, undefined/overflow rejection, warm/cold state and
disabled behavior. Existing focused CCP, MCL, BDOS, HISTORY/PDS and NDR checks
cover the shared paths.

`test_model2_var.py` executes emitted Model II resident/CCP code on the z80pack
CPU with controlled physical transfers. It covers STARTUP, MCL ordering, SUBMIT
substitution/cancellation, literal XSUB input, warm/cold state, exact optional
COM fit/overflow, NDR/PATH, CONFIG/STAT integration and disabled behavior. A
36-KiB GET/POKE/SAVE case overwrites the released bootstrap and then uses VAR.
Existing Model II foundation/MCL integration remains a regression. Production
reader tests check exact default COM floors on all three platforms.

`test_model4_var.py` uses disposable raw media in native trs80gp for startup
values, interactive substitutions, warm/full-COM return, undefined cancellation,
optional COM overflow and PDS/maximum-COM accounting.

This stage is focused implementation evidence, not a broad CP/M qualification
campaign or a completed 1.3 release. PR merging remains a maintainer action.
