## Review and corrections

All nine resident commands get implementation-specific quick reference screens. Exact case-insensitive /H, /HELP and /VER tokens are recognized anywhere in the bounded argument span, with space/TAB separation, help precedence and no normal operation. Longer tokens remain parser input. Unknown options/missing operands get brief syntax and a help hint; runtime failures retain their diagnostic and cleanup. Resident TYPE /P, COPY/MOVE /O and VER /V remain operational. Transient-only options retain colon-command hints, now explicitly labelled as additional transient features.

The preserved candidate did not distinguish numeric resident identification from the corresponding transient. This review corrects it to e.g. `DIR 1.0 (018, Resident RCP)`; transient DIR uses its own revision. The resident screens advertise resident syntax, not the COM implementations' extra switches. The six derived COMs embed shared resident identity data, so their bytes also change. Revision assignments are RCP 017 to 018, DIR 013 to 014, USER 009 to 010, CLS 010 to 011, VER 011 to 012, COPY 011 to 012 and MOVE 003 to 004. No CLS/USER/MOVE COM is added to distribution membership.

Source preparation changes eight eligible adjacent dispatch jumps to relative jumps to stay within the existing relocation header. Native heading padding uses explicit zero bytes instead of the unsupported ZSM4 DS count,fill extension. Native/cross parity verifies the resulting payloads.

The authoritative component policy was followed: compare reference/candidate at the same component revision and display state, verify changed executable bytes, then verify final revision assignments. Fourteen per-target assignment receipts and matching selected-input baselines are retained. No unrelated baseline records were updated. Automatic default builds select assigned identities without a display override and reproduce identically for z80pack and trs80gp. Shared generator changes remain relevant inputs for other consumers; later whole-release builds must review/requalify their output rather than copy old package receipts.

## Validation and limits

The [evidence index](evidence/2026-11-06-v1.0.1-utility-queries/results.json) binds every final artifact to hashes, input records, assignment receipts, logs and platform captures. Current bounded results:

- 735 relocated resident query/rejection cases at 4000h, 8101h and A000h: exact screens, aliases, precedence, boundaries, hostile BDOS scratch registers, FCB/tail/stack guards and ownership. Query stack peak 22 bytes. Additional existing feature-hint cases pass.
- 84 compiled queries for the six derived transients: version identities, aliases, precedence, TAB/max-tail and preserved command tails. COPY retains its existing specialized transient help; its alias equivalence oracle is its canonical help output.
- Resident TYPE compiled paging/EOF/abort/error/DU-restoration and REN positional/protection regressions pass.
- Supplemental actual-cpmsim regressions: 28 resident COPY/MOVE selection/preflight cases, 22 resident REN syntax/selection/protection cases, and resident TYPE selectors, protected text, paging, EOF/abort and unchanged-source checks pass on the final RCP. The harness uses an explicit simulator-path adapter and a clean private base; no product code is altered for these runs.
- Nine component registry, thirteen selected-input and fourteen revision-policy tests pass; registry projection and whitespace checks pass.
- Native CP/M ZSM4/LINK builds match RCP payload and all six derived COMs byte for byte. Native assembly alone is not guest behavior qualification.
- cpmsim: forty resident-only query/error/operation phases, absent matching COMs, COPY/REN/ERA/MOVE, overwrite refusal/replacement, all-files ERA refusal, independent file/readback/filesystem checks and repeated upper-12-KiB overwrite/WBOOT reconstruction. TPA ceiling D501h.
- Model 4: forty corresponding phases on the final exact resident payload, with M4SCRN/ADM3A, captured output, independent file/readback/filesystem and reserved-area checks. TPA ceiling CA01h. This is the normal 80-column Model 4 configuration.

Reference RCP is 6,828 code/data bytes, 6,912 allocated, 8,436 carrier bytes and 740 relocations. Final RCP is 8,045 code/data bytes, 8,192 allocated, 9,653 carrier bytes and 743 relocations, retaining the 1,536-byte header and 10,240-byte allocation on 2-KiB disk blocks. The additional 1,280 bytes of command-environment allocation are reclaimable; no lower transient TPA ceiling is inferred from that increase. Runtime receipts measure the actual ceilings and reconstruction behavior.

All nine help screens use CRLF ASCII and fit 9-11 lines and at most 61 columns, within the specified 23-by-79 limit. They exceed 40 columns (the common /VER footer is 51 columns; COPY/MOVE reach 61) and will wrap at 40 columns. No dedicated 40-column help mode, 40-column Model 4 execution or universal /40 promise is asserted. The UI matrix explicitly limits /40 to individual utilities' own modes. A requirement for unwrapped 40-column help would need a further presentation change and retest.

Known broader validation limitations are explicit. `test_utility_ui_inventory.py` fails with missing FDB in the UI matrix, identically on untouched main; this pre-existing documentation gap is outside this patch. The whole `test_utility_versions.py` sweep cannot run from this focused build because STAT.COM and other unrelated prerequisites are absent; the focused current-payload suites above cover all seven affected components. Frozen-package acceptance, paired replacement media, full utility operation coverage and physical hardware qualification are not claimed. These are release promotion gates, not evidence that the old archives contain this change.

A supplemental operation-runner attempt inherited user-5 files from the preceding qualification fixture and failed its final exact-inventory assertion. A private cleaned base is used for the rerun; this fixture failure is retained rather than counted as a utility defect.

Initial missing-default-simulator and relative-path attempts, and LaunchServices preflight 1100, are retained separately. ## Reproduction

Build RCP and the six transients with `python3 tools/build_rcp_cpx.py` and `python3 tools/build_rcp_transients.py`, then run `python3 tools/test_resident_feature_hints.py`, `python3 tools/test_resident_type.py`, `python3 tools/test_resident_ren_mapping.py`, the three component test scripts and `python3 tools/component_registry.py --check`.

For either platform, run `python3 tools/test_utility_query_media.py --resident --operations --platform PLATFORM --system SYSTEMS --simulator ABSOLUTE_CPMSIM --output NEW_DIRECTORY`, where PLATFORM is cpmsim or model4. SYSTEMS must contain paired z80pack/trs80gp report.json, images and diskdefs. The exact reference image hashes are in the receipts. A macOS graphical launch context is needed for Model 4. Native parity uses the existing `build_native_rcp_cpx.py` and `build_native_rcp_transients.py` with explicit --cpmsim, --system-disk, --disk-template and --tools paths; exact commands/inputs are retained in the evidence archive.

After approved merge, build replacement v1.0.1 packages from the accepted commit and qualify their exact members. Preserve v1.0 archives and historical receipts. No merge, tag, publication or release replacement is performed here.
