# BetterCP/M 1.3: PDS ABI proposal for maintainer review

Status: maintainer-approved design; implementation proceeds in reviewable stages. Baseline: v1.2
`a496016b8f6430bc96ced32b339629bd566425e1`.
Read with `1.3-MCL-SEMANTICS-PROPOSAL.md` and the locked implementation scope.

## Recommendation

Keep the existing BM version-1 extension descriptor and its offsets. Introduce
a separately versioned, fixed-address PDS v2 header containing three owner
lengths. Derive owner addresses by addition. Allocate only at cold boot. Provide
no callable allocation service, third-party owner registry or resident lookup
API. Reconstructible consumers can share a small assembly include for lookup
and validation; no general abstraction is needed.

This is a bounded directory with implicit owner IDs, not a general heap. Three
length words are enough for the three locked owners; storing IDs, pointers and
individual versions again would cost bytes without adding a 1.3 capability.

## Why the existing descriptor must stay separate

`src/system/gateway.mac` defines BM version 1 at LY_SYS+80h. The +8 word has
both ECB_PDSLOW and ECB_RSXLOW labels. `r3final.mac` passes that word's address
to `r3comit.mac:RC_PUBLISH`, which writes the installed RSX low boundary and
publishes its value minus three as the TPA ceiling. Thus this word is not an
immutable PDS location when RSXs are loaded, despite the old PDS alias.

Preserve +8's actual live RSX-boundary behavior. Preserve +16's live exclusive
TPA ceiling and page-zero gateway semantics. Correct the misleading PDS alias
and documentation in the implementation. Do not reinterpret existing fields.
STAT currently requires BM version 1 (`stat.mac:MEMREPORT`); changing BM to 2
would unnecessarily affect RSX, CPX and other descriptor users.

PDS-aware 1.3 modules discover the new header directly at LY_SYS-12, using
their existing layout binding. This does not promise binary compatibility for
old modules that hard-code the HISTORY address. Rebuild/bind internal modules
together using the existing checked-build compatibility mechanism. There is
no program-visible variable or general PDS API.

## Exact proposed header and allocation layout

All words are unsigned little-endian. Header address = LY_SYS-12.

| Header offset | Bytes | Meaning |
| --- | ---: | --- |
| 0 | 2 | ASCII `PD`, published last after successful cold composition |
| 2 | 1 | PDS ABI = 2 |
| 3 | 1 | Header/directory size = 12 |
| 4 | 2 | Owner 1 HISTORY allocation length, zero = disabled |
| 6 | 2 | Owner 2 MCL allocation length, zero = disabled |
| 8 | 2 | Owner 3 VAR allocation length, zero = disabled |
| 10 | 2 | Header checksum: sum of six 16-bit words = zero modulo 65536 |

The ABI defines all three owner formats as version 1. No unknown owners or
per-owner version negotiation in 1.3. A future incompatible layout uses a new
PDS ABI. Checksum covers immutable metadata only, not writable payload.

Let H, M and V be the three lengths, and T = LY_SYS-12:

```
PDS low      = T-H-M-V
HISTORY base = PDS low                 length H
MCL base     = PDS low+H               length M
VAR base     = PDS low+H+M             length V
metadata     = T                      length 12
PDS total    = H+M+V+12
```

No alignment gaps are required on Z80. Zero-length owners have no object and
must never be dereferenced. With no RSXs installed, the movable three-byte
gateway is at PDS low-3. RSX packing starts below PDS low, not below LY_HIST;
removing the last RSX restores the computed boundary. Command reconstruction,
CPX placement, loader limits, page-zero publication and STAT must all use the
same computed bounds. The linker-origin LY_TPA is no longer an active ceiling.

## Capacity choices and initialization

Proposed CONFIG choices (allocation bytes include owner control bytes):

| Owner | Off | Small | Normal | Large |
| --- | ---: | ---: | ---: | ---: |
| HISTORY | 0 | 128 | 192 | 384 |
| MCL | 0 | — | 128 (On) | — |
| VAR | 0 | 128 | 256 | 512 |

HISTORY retains its ten-byte control layout and packed records; Normal retains
182 record bytes. Off disables recall/recording, preserving ordinary editing.
Small still has room for at least one maximum input record under the existing
history policy only if that record fits; over-capacity records follow the
existing history handling rather than truncating commands. Variable capacities
are proposals, not measured usability requirements. Reject capacities outside
these choices rather than accepting arbitrary saved lengths.

VAR's owner-private representation can be a two-byte used-length followed by
packed length-delimited name/value records. Its transient command code may
move records on update/delete; this is bounded owner-table editing, not PDS
allocation or PDS compaction. No separate stored system-value table.

Cold composition zeros owner storage. HISTORY initializes its existing BH/v1
object; MCL initializes empty; VAR initializes used length zero. Publish PD
only after complete initialization and valid bounds. WBOOT never rereads saved
composition or recalculates lengths from disk. It validates the active header
and reconstructs code around the existing allocations, preserving owner data.

Reject header length/version/checksum errors, invalid capacity combinations,
arithmetic overflow/underflow and out-of-profile bounds before any owner access.
Do not guess a default layout during WBOOT: a wrong lower boundary can overwrite
resident state. Stop reconstruction with a concise cold-boot-required diagnostic.
For a structurally valid directory but malformed owner payload, reset only that
owner and report it; reject malformed MCL before any pending command dispatch.

## Saved configuration: explicit BCST v2 extension

Recommend extending the existing two-record BCST startup configuration, keeping
it 256 bytes and preserving its 16-byte header, 126-byte startup capacity and
16-bit checksum algorithm. Change its version from (1,0) to (2,0). At offsets
142–149 store eight bytes: `CE`, extension version 1, HISTORY choice (0–3),
MCL choice (0–1), VAR choice (0–3), then two reserved zero bytes. All other
unused bytes stay zero. The checksum covers the entire record as today.

This needs an explicit version change: `tools/startup_record.py:parse` and
`ccp.mac:CCP_STZERO` currently reject nonzero reserved bytes. Silently writing
configuration into BCST v1 would violate that contract.

New readers accept valid v1 and v2. V1 supplies its existing startup command
and the qualified 1.3 default owner choices. Missing/invalid records produce a
diagnostic and qualified defaults; unsupported versions are not overwritten
unless the user explicitly saves a replacement. CONFIG warns that saving v2
requires 1.3 boot/startup readers; downgrading requires reinstalling compatible
defaults. Old tools must not be used to edit a 1.3 system configuration.

Read and compose once on true cold entry, before installing RSXs/CPXs or the
final movable gateway. Use a transient boot/reconstruction worker and existing
BIOS disk access, not permanently resident CONFIG code. `SYS_ENTER` currently
calls `SYS_INIT` before reconstruction: split bootstrap initialization from final
boundary publication so no consumer uses a half-composed layout. Keep the
temporary cold-load buffer outside both the final PDS and the active loader
stack. Integrate all supported boot paths, package builders and SYSBUILD/SYSGEN
copies of these protected records, not only the host record builder.

CONFIG keeps active choices derived from the live header, an editable pending
copy and the verified saved record. Pending-only save writes cold settings;
all-current save retains its existing meaning for other domains while including
pending PDS choices. Neither operation changes active allocations. Read back
and validate the whole saved record. A startup-command edit preserves PDS
choices and a PDS edit preserves the startup command. Retain existing save
failure/recovery behavior; do not claim new power-loss atomicity.

## Measured baseline and default policy

Freshly assembled canonical Model 4 components:

| Component | Bytes |
| --- | ---: |
| Gateway | 248 |
| Unified BDOS including private stack | 3,451 |
| Extension services | 420 |
| Disk services | 942 |
| BIOS | 757 |
| File loader | 145 |
| Drive tables | 576 |
| Resident span through RSX workspace | 6,588 |
| Entire protected span, including PDS/work buffers/gateway | 7,935 |
| Unoccupied inter-component padding reported by current tool | 8 |

The eight bytes are three after BDOS and five after extension services. These
are candidate gaps, not proven reclaimable memory. Reserved buffers, private
stacks and optional RSX space are not free padding. BIOS has zero slot slack.
Even reclaiming all eight bytes would not pay the proposed default's 12-byte
metadata overhead at the existing COM floor. New resident cancellation code
has additional cost that must be measured.

Profile-derived boundaries and hypothetical costs with no code changes or
repacking (runtime maximum-COM boundary tests have not been run):

| Enabled owners | PDS bytes | cpmsim / Model II max COM | Model 4 max COM |
| --- | ---: | ---: | ---: |
| v1.2 HISTORY | 192 | 57,344 | 54,272 |
| v2 HISTORY Normal | 204 | 57,216 | 54,144 |
| v2 HISTORY Normal + MCL | 332 | 57,088 | 54,016 |
| v2 HISTORY Normal + VAR Small | 332 | 57,088 | 54,016 |
| v2 HISTORY Normal + MCL + VAR Small | 460 | 56,960 | 53,888 |
| v2 HISTORY Normal + MCL + VAR Normal | 588 | 56,832 | 53,760 |

cpmsim/Model II raw space is 57,345; Model 4 raw space is 54,273.
Formula: floor((raw space - net protected growth)/128)*128.
Metadata-only default needs at least 11 net bytes recovered, plus every new
resident byte, to retain the floor. HISTORY+MCL needs 139; all three with VAR
Small need 267. These thresholds assume unchanged owner capacities elsewhere.

Recommend HISTORY Normal on, MCL off, VAR off as the conservative default
candidate. Enabling optional owners is supported through CONFIG and carries
an explicit TPA preview. This candidate is NOT release-qualified until the
12 metadata bytes and resident growth are paid for without reducing the floor.
The table above records proposal-time arithmetic. Fresh builds on all three
platforms now confirm the twelve-byte recovery and unchanged default floors;
see [foundation evidence](1.3-PDS-FOUNDATION.md). Full 1.3 release qualification
is not claimed by this foundation stage.

Baseline reproduction: run `python3 tools/build_bdos.py`,
`python3 tools/build_fileloader.py`, `python3 tools/build_system.py`, then
`python3 tools/report_memory_layout.py` in a clean canonical checkout. Profile
arithmetic comes from `build_profiles.profile_inputs` for `cpmsim-fullram` and
`model2-fullram`. These checks assemble components and calculate layouts; they
do not execute the proposed ABI, saved format or MCL semantics.

If focused packing cannot meet that default, return for review with exact
evidence. Do not silently lower the floor, shrink history, or ship a second
legacy PDS mode to hide the cost. Larger optional profiles may lower TPA.

STAT MEM reports PDS total, metadata 12, each enabled owner allocation and
the current record-aligned maximum COM from the live gateway. CONFIG previews
the next-cold unloaded maximum; identify installed-RSX reductions separately.
Do not subtract PDS twice from an already lowered live gateway.

## Reviewed alternatives and approval

- A generic ID/offset/length/version directory is unnecessary for three fixed
  consumers and costs more. Choose it only if a concrete 1.3 need appears.
- Bumping BM to 2 couples unrelated descriptor users to this change. Keeping
  BM1 and independently versioning PD is smaller in compatibility scope.
- Placing metadata in an assumed resident hole has no demonstrated memory win;
  it merely changes which accounting category bears the bytes.
- A second disk record avoids BCST versioning but introduces placement and
  persistence coordination. Reusing the existing versioned record is simpler.

The maintainer approved the 12-byte fixed-owner header, independent PD2/BM1
versioning, BCST2 extension and conservative default, subject to measured floor
compliance. The foundation preserves the approved capacity choices.
Implementation must add focused owner/cold/warm/config/RSX-boundary validation
and run exact maximum-COM tests on all three platforms before final defaults.
