# Engineering Specification 117: CP/M 2.2 Utility Inventory

Date: 2026-09-03

## Purpose

This inventory defines what “reproduce the stock transient commands” means for
BetterCP/M. It separates Digital Research's portable utility baseline from
system-generation programs, source/support artifacts, and OEM additions.

## Stock Digital Research executable baseline

| Program | Role | BetterCP/M class |
|---|---|---|
| `ASM.COM` | Two-pass 8080 assembler producing HEX, PRN, and symbols/diagnostics | Development tool |
| `DDT.COM` | Dynamic debugger: load, inspect, modify, trace, disassemble, and execute | Development tool |
| `DUMP.COM` | Hexadecimal file display | File inspection |
| `ED.COM` | Command-oriented text editor with CP/M file/recovery behavior | Development and file tool |
| `LOAD.COM` | Convert Intel HEX into executable COM form | Development tool |
| `PIP.COM` | Copy, concatenate, transform, and transfer files and logical devices | Essential file/device tool |
| `STAT.COM` | Report disk/file/device state; set attributes and device assignments | Essential system/file tool |
| `SUBMIT.COM` | Perform positional substitution and queue batch commands | Command automation |
| `XSUB.COM` | Feed submitted input to programs that read the console buffer | Command-automation companion |
| `MOVCPM.COM` | Relocate/configure the supplied CP/M image for a memory size | Installation-dependent system tool |
| `SYSGEN.COM` | place or retrieve a bootable CP/M system image in reserved tracks | Installation-dependent system tool |

This gives a canonical total of **eleven stock transient executables**.

## Commands that are not transient utilities

The original CCP supplies `DIR`, `ERA`, `REN`, `SAVE`, `TYPE`, and `USER`.
BetterCP/M shall supply that complete set through BASIC.CPX. It shall also ship
matching transient `DIR.COM`, `ERA.COM`, `REN.COM`, `TYPE.COM`, and `USER.COM`
fallbacks. Those fallbacks reproduce their resident counterparts rather than
developing separate transient-only enhancements. `SAVE.COM` is the sole
inherent exception: loading it at 0100H would overwrite the memory that SAVE
is required to write.

BetterCP/M additionally places `CLR` in BASIC.CPX and shall provide a matching
`CLR.COM` fallback. It is a BetterCP/M distribution command, not part of the
stock DRI compatibility baseline.

BetterCP/M also supplies `VER` through BASIC.CPX and matching `VER.COM` forms.
`WARM.COM` is transient-only for scripts and explicit workflows; interactive
warm boot remains the canonical `Ctrl-C` operation. Transitional core copies
of VER and WARM may be removed now that their final command placements exist.

`CLR`, `CPX`, and `RSX` are BetterCP/M additions and are not counted among the
eleven stock programs.

## Distribution artifacts, not commands

Original or reconstructed distribution disks may also contain `BIOS.ASM`,
`CBIOS.ASM`, `DEBLOCK.ASM`, `DISKDEF.LIB`, `DUMP.ASM`, and other source,
configuration, sample, or documentation files. They matter to a complete
source distribution but do not expand the transient-command compatibility
list.

## OEM and Montezuma Micro additions

There is no single universal set of OEM utilities. The examined Montezuma
Micro distribution bundles programs including `CONFIG`, `DUP`, `MDIR`,
`EXBIOS`, `KEYDEF`, and modem/support software. Presence on that disk does not
by itself establish Montezuma Micro authorship. In particular, the archived
MDIR 2.1 source identifies MDIR as the community-developed **CP/M-2 Master Disk
Directory** by Jeff Hammersley, based on Ward Christensen's FMAP and Keith
Petersen's SDIR, with later revisions by Petersen and Ron Fowler. The exact
`MDIR.COM` on the Montezuma Micro disk should still be version-matched before
we claim that it is this particular build.

These programs can be worthwhile BetterCP/M distribution features—CONFIG is
already an architectural goal—but they remain distinct from the stock DRI
utility baseline. The inventory must separately record who authored a utility,
which distribution bundled it, and whether BetterCP/M recreates or redistributes
it.

Likewise, `FORMAT` is necessarily hardware and media dependent. BetterCP/M
needs formatting facilities for supported platforms, but no single stock
`FORMAT.COM` behavior can be claimed for CP/M 2.2 as a whole.

## Implementation groups

The inventory suggests four practical groups without yet fixing development
order:

1. Essential operation: `PIP`, `STAT`.
2. Inspection and automation: `DUMP`, `SUBMIT`, `XSUB`.
3. Native development: `ED`, `ASM`, `LOAD`, `DDT`.
4. System installation: BetterCP/M equivalents for `MOVCPM` and `SYSGEN`.

Each replacement still requires its own behavioral specification and
reference comparison. A matching filename alone does not establish
compatibility.
