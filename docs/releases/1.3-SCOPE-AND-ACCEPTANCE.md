# BetterCP/M 1.3 focused release acceptance

Feature baseline: main `bcd27a0a` after PR #687. PDS/HISTORY/CONFIG, MCL and
VAR implementations are merged. Subsequent work is release identity,
documentation, packaging or demonstrated blockers. No additional 1.3 features.

Defaults remain HISTORY 192, MCL Off, VAR Off. Default total PDS is 204 bytes,
including 12 bytes of metadata. Maximum complete-record COM capacity must stay
57344 bytes on flat-64K cpmsim and Model II, and 54272 on Model 4. Enabling
optional owners carries CONFIG/STAT's explicit memory cost. No floor exception
is authorized. NDR remains in NDR.RSX; FLOW and HISTORY.RSX are not 1.3 work.

Reuse the focused implementation evidence from PRs #683–#687. It covers owner
composition, warm/cold lifetime, history, MCL, VAR, SUBMIT/XSUB, NDR/PATH and
private carrier reconstruction. Reuse applies to matching source inputs;
record actual final-media hashes and investigate functional differences.

Candidate preparation uses `tools/prepare_release_13.py` and the eight-asset
layout `metadata/release-assets-1.3.json`. Candidate construction and package
integrity are separate from runtime acceptance. Pending smoke is permitted
only by the explicit `1.3-focused` policy; a 1.2 receipt cannot satisfy it.
Every package remains CANDIDATE/NOT ACCEPTED until its acceptance gates pass.
Historical software packages, locks and evidence must not be rewritten.

Required automated checks: registry/generated identity consistency, candidate
headings, documentation links, source selection, independent System inventories
and file readback, matching CONFIG overlay/modules, private package binding,
archive integrity/ledgers and three-platform exact default COM boundaries.
Record source commit, selected input fingerprints and actual artifact hashes.

Run one short final-media smoke on each platform: boot, confirm 1.3 candidate
identity and default memory, query STAT MEM, inspect CONFIG F active/pending
choices, use one NDR/PATH command and one ordinary COM. A disposable cold-boot
configuration with MCL/VAR enabled should exercise one assignment/substitution
and queued return, then confirm optional costs. Never overwrite release masters.
Retain existing HELP, TCAP and NOAH 1.0 (021) identities/behavior; reopen their
checks only for a changed input or demonstrated failure.

Do not start a broad CP/M, terminal, HELP-topic, NDR, SUBMIT/XSUB, disk-install
or conformance campaign. A focused gate that fails remains pending/failed and
gets a narrow fix with relevant checks. Final eight archives, source offer,
documentation edition, installation smoke and maintainer acceptance remain
explicit release gates. This specification does not authorize tagging,
publishing, baseline promotion or PR merging.
