# BetterCP/M 1.0.1 release packages

The release uses six independently downloadable packages: System for cpmsim,
System for Model 4, Utilities for each platform, Source, and Documentation.
The [asset manifest](../../metadata/release-assets-1.0.1.json) defines their
names and roots. The locked 1.0 assets and metadata remain historical records.

The release source includes merged main through PR #640, the maintenance fixes,
the explicitly approved PIP selectors, and the four qualified supplemental
format definitions. The standard System catalogue stays at 108 entries; the
supplement is delivered on Utilities media and in Source. The cpmsim System
retains the existing 32-byte checksum capacity and BIOS layout. ATONSS,
ATONDS and PT2SS, and the capacity expansion they require, are deferred to
1.1 consideration. Source retains the experimental definitions and historical
qualification evidence separately from the four-entry release supplement. The
[release notes](RELEASE-NOTES-1.0.1.md) record platform restrictions and load order.

Assembly must explicitly select `--version 1.0.1`. The default 1.0 packaging
route still refuses the non-documentation lock. A clean committed source,
matched rebuilt System/Utilities receipts, pinned runtime reconstruction,
independent inventories, source/notices, and archive readback checks are
required. Never relabel historical qualification as a test of new image bytes.

Documentation contains the four maintained Markdown manuals plus their selected
supporting references and original examples. Omitted source/history references
are pinned to the release source; no generated PDF/DOCX edition is asserted.

Final byte identities, acceptance receipts, release notes and checksums must be
prepared before tagging or publishing. New release work does not reopen or
replace the 1.0 archives. The release record must distinguish tested software
and host behavior from physical-media, unsupported format/platform, live-resize
and hardware limitations.
