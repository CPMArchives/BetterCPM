# BetterCP/M Stage 7 — Retained Implementation Contracts
## Consolidated Acceptance Specification

**Status:** Accepted and source-audited. Stage 7 complete.

## 1. Purpose

Stage 7 translates the architecture frozen in Stages 3–6 into implementation-ready acceptance contracts for the retained BetterCP/M 1.0 scope. It does **not** implement those contracts, redesign accepted architecture, restore deferred features, choose the final convenience-utility inventory, or perform the Stage 8 documentation reconciliation.

For each retained facility, this specification states required behavior, exclusions, acceptance criteria, evidence, governing specification, and source-verified implementation status.

### Status vocabulary

- implemented but requires final qualification
- partially implemented
- implementation required
- conditional candidate
- deferred
- implementation status verified by source audit

## 3. Normative retained contracts

### 3.1 System core
BetterCP/M 1.0 remains a CP/M-compatible CCP→BDOS→BIOS system. Cold boot constructs deterministic new runtime state; WBOOT preserves or resets state according to each owner's lifecycle. Page-zero vectors remain valid across boot and reconstruction. Prospective resident changes validate before atomic publication; failure preserves the previous usable state. The default configuration retains at least 53 KiB usable TPA. Final extended-BDOS production selectors are 176–183 and dispatch is explicit rather than a blanket high-function capture.

### 3.2 Bounded PDS
The 1.0 PDS is exactly 192 bytes and contains only HISTORY v1: bytes 0–5 persistent header, bytes 6–9 owner-private working state with no persistent ABI meaning, and bytes 10–191 packed history data. Cold boot initializes a valid empty history unconditionally. WBOOT/reconstruction preserve valid history. Invalid history resets safely. No allocator, owner directory, runtime growth, migration, compaction, or speculative reserve exists.

### 3.3 ROM profile
The ROM profile executes retained immutable system code directly from an enforced write-protected region under cpmsim. Mutable state, profiles, PDS, stacks, transaction state, and workspaces reside in writable RAM under natural owners. Runtime operation and reconstruction do not patch executable code or immutable descriptors. Static workspace sharing requires proven mutually exclusive lifetimes. Copying the ROM image to RAM and executing the copy does not qualify.

### 3.4 Command environment and extensions
The retained command environment provides CCP initialization/WBOOT reconstruction, transactional CPX and BRSX-v2 RSX profiles, stateful reconstruction, bounded built-in history, retained line editing, ordinary drive/user command lookup, SUBMIT/XSUB, final cursor/printer-echo selectors, and clean failure recovery. Navigation commands are recognized first, core compatibility commands second, CPXs third, and transient lookup last. `B:`, `5:` and `C3:` change the current drive/user; qualified commands and directory requests do not silently change the caller's current drive/user.

CPX acceptance covers command enumeration, dispatch and chaining, core-command bypass, return and termination, initialization and shutdown, WBOOT reconstruction, unload, failure recovery, ordering, declared dependencies, conflicts, and dependency-cycle rejection. RSX acceptance covers load, initialization, interception and chaining, callable-service publication and resolution, stateful movement/reconstruction, unload, rollback, failure and reentrancy boundaries. Arbitrary conforming modules must be handled from their declared metadata rather than a built-in name list. BRSX v1 is not a release compatibility requirement. Every unknown metadata-v1 record type rejects without changing the live profile.

### 3.5 Disk-format system
Runtime authority resides in BIOS-owned physical-drive records and self-contained normalized logical bindings. FDF/FDB are validated inputs/provenance, not runtime indirection. Saved bindings reproduce boot operation without first reading DISK.FDB. Observed and derived state do not silently rewrite configured semantics. Uniform-sector core geometry and retained mixed-sector capability are required. Missing capability rejects cleanly. Mixed-track remains deferred. Sector placement/skew and claimed cpmtools interoperability require raw and filesystem-level evidence.

### 3.6 CONFIG, DUP, SYSBUILD, SYSGEN, platforms
CONFIG is physical-first, distinguishes candidate/active/saved state, and manages dependency invalidation explicitly. The optional startup command executes exactly once after cold initialization and required service availability. It never executes on WBOOT or RSX/CPX reconstruction. The executed flag is set before dispatch; failure returns to the prompt without retry. Empty configuration disables the action, true cold boot clears the flag, and the documented recovery gesture suppresses startup. CONFIG must inspect, edit, clear and immediately test the configured action.

DUP uses actual backend capabilities and rejects known-unsupported formats before knowingly destructive work. SYSBUILD creates and verifies `SYSTEM.SYS` from exactly these nine stable products: `BOOT.BIN`, `STAGE1.BIN`, `RESIDENT.BIN`, `CCPRELOD.BIN`, `RSXSEL.BIN`, `CONFIG.BIN`, `RSXLOAD.BIN`, `RSXRESOL.BIN`, and `CCP.RLM`. Missing or incompatible required products fail cleanly. SYSGEN installs into compatible reserved/system areas while preserving the ordinary filesystem. Required targets are trs80gp/TRS-80 Model 4 and z80pack/cpmsim only.

### 3.7 File attributes
R/O, SYS, and ARC are ordinary retained CP/M metadata. All three are inspectable, modifiable, and preserved through applicable operations. R/O is enforced. SYS does not require enhanced cross-user visibility. ARC is metadata only. Timestamps are not a prerequisite. Stage 7 does not choose the final utility that exposes attribute inspection/modification.

### 3.8 TIME and historical clock compatibility
Native clock access is callable TIME ABI 1.0 through Function 182, using the canonical five-byte day/BCD record. GET is coherent and validated. SET semantics are complete; read-only providers return SET_UNSUPPORTED. FreHD/trs80gp and z80pack/cpmsim providers implement the same native ABI. TIME.COM is a native client independent of historical frontends. Existing providers and TIME.COM establish a partial implementation; production-selector migration and TIME.COM SET remain implementation work.

P2DOS.RSX ships with 1.0 but is optional to load. It owns Functions 200/201, resolves TIME per call, retains no provider address, and duplicates no hardware driver. Success returns `A=00h, HL=0000h`; claimed failure returns BetterCP/M extension `A=FEh, HL=00FEh`; absence returns `A=FFh, HL=00FFh`. DE/SP/IX/IY are preserved. Failed GET leaves the caller's record unchanged and claimed failures do not chain.

### 3.9 Build, packaging, and release
The release process begins from an exact source revision and recorded external inputs. Host/native workflows have complete declared dependencies and explicit byte- or semantic-equivalence rules. Generated FDB, binaries, SYSTEM.SYS, manifests, and platform media correspond to frozen authoritative inputs. Every distributed artifact has sufficient provenance/version/hash information. Release candidates are frozen as exact artifacts before qualification; rebuilding creates a new candidate.

### 3.10 Final qualification
BetterCP/M 1.0 is qualified against exact frozen RC artifacts on trs80gp/TRS-80 Model 4 and z80pack/cpmsim. Qualification includes the complete CP/M 2.2 conformance suite, retained BetterCP/M-specific tests, genuine ROM XIP, TPA, reconstruction/rollback, disk/install round trips, file attributes, TIME/providers, and P2DOS. The final package contains the same qualified artifacts.

## 4. Conditional 1.0 candidates

### Four-byte Function 104/105 frontend
CP/M 3/DOS+ convention: Function 104 consumes four bytes `DD DD HH MM` and supplies native seconds 00; Function 105 writes exactly four bytes and returns BCD seconds in A. Admission requires a small stateless per-call TIME adapter, no OS impersonation/timestamps/SCB, guard-byte safety, SCTIME qualification, measured resident cost, preserved default TPA, and proven mutual exclusion from the five-byte frontend.

### Five-byte Function 104/105 frontend
Z80DOS convention: Function 104 consumes `DD DD HH MM SS`; Function 105 writes all five bytes and returns A=00h. Admission requires the same architectural/cost/lifecycle gates, DATE501 qualification, and mutual exclusion.

Neither frontend is a release gate unless actually admitted into the RC. Failure of the admission gates defers the candidate to later 1.x.

## 6. Cross-cutting acceptance gates

1. **Exact artifacts:** qualification attaches to hashes of exact RC binaries/images/configurations, not source intentions.
2. **Two required targets:** trs80gp/TRS-80 Model 4 and z80pack/cpmsim.
3. **CP/M compatibility:** complete CP/M 2.2 conformance suite must be run and every non-pass dispositioned.
4. **53 KiB TPA:** default configuration retains the 54,272-byte maximum record-aligned COM image.
5. **Transactional publication:** failed prospective CPX/RSX changes never partially replace published state.
6. **ROM XIP:** cpmsim qualification enforces write protection and executes protected code in place.
7. **Natural ownership:** PDS is HISTORY-only; other mutable objects remain with natural owners.
8. **Disk safety:** unsupported geometry/capability rejects rather than approximates; system installation preserves ordinary filesystem.
9. **Historical compatibility at the edge:** native TIME remains independent of P2DOS/104/105 frontends.
10. **Build reproducibility/provenance:** every distributed artifact is traceable to frozen inputs or approved prebuilt provenance.
11. **Third-party permission:** provenance alone does not authorize redistribution.
12. **Conditional admission:** once a conditional feature enters the RC, its complete acceptance contract becomes release-gating.
13. **Deferred means non-gating:** missing deferred features cannot block 1.0.
14. **Rebuild invalidation:** changed artifacts lose prior qualification and require relevant retesting.
15. **Package identity:** distributed artifacts must match the qualification manifest.

## 8. Bounded source-audit disposition

The Stage 7 source audit is complete. Its eight bounded categories produced the
following dispositions:

1. **PDS and TPA:** current cold entry can preserve a valid-looking history
   object, contrary to the unconditional empty-object cold-start contract. The
   correction is implementation work. The exclusive TPA ceiling remains
   `D501h`, allowing a 54,272-byte record-aligned COM image: exactly 53 KiB.
2. **CPX, RSX and metadata:** Stage 3 reconstruction is implemented and
   qualified. Final CPX/RSX interface behavior remains implementation work.
   The metadata normalizer currently skips unrecognized records; it must reject
   unknown metadata-v1 record types without changing the live profile.
3. **Commands and batch:** current dispatch is navigation, core compatibility
   commands, CPXs, then transient lookup. Ordinary DU navigation and qualified
   lookup are implemented. SUBMIT/XSUB and retained editing/history behavior
   are implemented and require final release-candidate qualification.
4. **Disk path:** normalized active physical and logical representations exist.
   Text `DISK.FDF` and `FDF.RSX` paths exist. The production FDB compiler and
   reader, broader saved-state/CONFIG behavior, startup command and remaining
   DUP integration are implementation work.
5. **Native build:** Engineering Specification 139 Native System Build records the implemented
   SYSBUILD/SYSGEN workflow and the nine stable SYSBUILD products named in
   Section 3.6. Final native rebuild and installation qualification remains.
6. **File attributes:** Function 30, STAT exposure, preservation and read-only
   enforcement are implemented and have focused tests. Final RC qualification
   remains; enhanced SYS visibility and timestamps remain outside 1.0.
7. **TIME:** TIME.COM and both required read-only providers exist. Production
   selector migration, TIME.COM SET, final qualification and P2DOS.RSX remain.
8. **ROM:** cpmsim write-protection instrumentation and focused guard tests
   exist. BetterCP/M's ROM/RAM split, integrated XIP image, workspace lifetime
   proof, stack measurements and full qualification remain implementation work.

The detailed source evidence is retained in Engineering Specification 154.
Final workspace, stack, clean-build, optional-adapter, package-identity and
release-candidate measurements are acceptance evidence required by this
specification; they were not prerequisites for publishing it.

## 9. Contradictions or missing authoritative material

The Stage 7 analysis identified no new architectural contradiction requiring redesign. The following are implementation and documentation items to resolve during the implementation program or Stage 8:

1. **Cold HISTORY initialization:** frozen Stage-5 contract requires unconditional empty HISTORY on true cold boot; earlier source audit found current `CCP_HINIT` preserves valid-looking history. This is implementation work, not an architecture conflict.
2. **ROM placement details:** ownership/XIP rules are frozen, but final RAM addresses, overlay groups, stack sizes, and final ROM boundary must not be invented unless already authoritative. These are implementation/qualification facts.
3. **Command documentation:** the programmer guide's statement that CPXs receive first refusal contradicts source and Architecture Specification 6. Stage 8 must correct it to navigation, core commands, CPXs, then transient lookup.
4. **FDF/FDB implementation:** the Disk Format Definition Specification is authoritative; the production compiler and reader remain implementation work.
5. **File-attribute utility:** required capability is implemented, but Stage 7 does not choose the final utility that exposes it.
6. **Build equivalence:** byte-identical versus semantic reproducibility must be established per artifact from current tooling rather than assumed.
7. **Third-party redistribution:** provenance does not resolve permission. LINK.COM remains a concrete release check.
8. **Optional 104/105 frontends:** no architecture gap; admission remains conditional on post-P2DOS measurement and proven numeric-interceptor mutual exclusion.

## 10. Release qualification rule

BetterCP/M 1.0 qualification is complete only when:

1. the exact RC artifact set is frozen and hashed;
2. both required platform environments are recorded;
3. the complete CP/M 2.2 conformance suite is run on both targets;
4. every retained BetterCP/M-specific contract has sufficient evidence;
5. the 53 KiB TPA floor passes;
6. cpmsim ROM XIP passes under enforced write protection;
7. PDS cold/warm lifecycle passes;
8. CPX/RSX reconstruction and rollback pass;
9. required disk-format, CONFIG, DUP, SYSBUILD, SYSGEN, and installation paths pass;
10. required file attributes pass;
11. native TIME, both required providers, and P2DOS.RSX pass;
12. every admitted conditional feature passes its full contract;
13. every regression/non-pass has a recorded disposition;
14. build/package provenance and redistribution requirements are satisfied; and
15. the final package contains the same artifacts identified by the qualification manifest.

An unconditional retained-contract failure blocks release. A missing deferred feature does not. A conditional candidate blocks release only after admission into the RC.
