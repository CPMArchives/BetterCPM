# BetterCP/M 1.1 VER query disposition

The release image observations below distinguish resident dispatch from the
explicit transient. All three targets produce the same outcomes:

| Query | Observed behavior |
| --- | --- |
| `VER` | `BetterCP/M 1.1` |
| `VER /H`, `VER /HELP` | Resident help screen, including `/V`, `/H`, `/HELP` and `/VER` |
| `VER /VER` | `VER 1.0 (019-dev, Resident RCP)`; one-line identity |
| `:VER` | `BetterCP/M 1.1` |
| `:VER /H`, `:VER /HELP` | Transient help screen including `/BANNER` and standard help/identity switches |
| `:VER /VER`, `A0:VER /VER` | `VER 1.0 (013-dev)` and the shared Utilities / System Version Information block |

The independent component version/revision is not the package/Core OS version.
Resident help no longer returns `?`. However, the resident `/VER` identity still
lacks the shared multi-line identification block. [Issue #612](https://github.com/CPMArchives/BetterCPM/issues/612)
therefore remains open. This pre-existing UI difference is documented for 1.1
under the frozen scope's explicit VER disposition allowance; these observations
do not claim complete resident/transient UI conformance or close the issue.
No VER code change was made for this disposition.

All nine queries ran against writable copies of each image. Model 4 uses
physical key injection; native commands were paced to avoid entering the next
query before the previous one returned. Earlier fast-input diagnostics with
missing command prefixes are not acceptance evidence. cpmsim uses a rendered
terminal so integrated cell-positioning output is observed correctly.
