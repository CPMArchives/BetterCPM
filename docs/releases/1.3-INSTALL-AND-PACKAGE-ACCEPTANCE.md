# 1.3 focused installation and package acceptance

The reviewed starting source is merged main `3afac0cb` after PR #691.
Rebuilding it exposed a Model 4 distribution inconsistency: the boot disk's
BCST selected `SUBMIT STARTUP`, while the bundled ordinary `SYSTEM.SYS` retained
the native reference's empty startup command. Installing that file therefore
did not reproduce the distribution's startup configuration.

Packaging-fix producer `91167ada` derives only the install package's 256-byte
BCST from the same distribution command used for the boot disk. It records the
original artifact hash and verifies equality with the actual disk record.
The ordinary header and every other package byte remain unchanged. Native
reference products, historical preparation paths, resident code and default
PDS composition are unchanged. Only `SYSTEM.SYS` changes in the Model 4 System
inventory; cpmsim and Model II images remain byte-identical to the final-main
rebuilds that passed installation.

## Focused gates

The installation driver uses private copies of the actual prepared System
images. It erases their protected tracks, retains the complete populated
filesystem, and runs the delivered `SYSGEN SYSTEM.SYS B:` with confirmation.
It compares every filesystem byte across installation, checks protected bytes
against the expected package/boot binding, then independently cold-boots the
installed disk and queries VER, STAT MEM and STAT's ordinary transient identity.
The Model 4 setup helper selects a compatible SYSTEM B: through the existing
Function 181 contract; it is not added to release media.

CP/M boot-binding normalization is checked explicitly: three geometry bytes on
cpmsim and the E0h-to-A0h binding flag at raw offset 7018 on Model 4. Model II's
installed protected region is identical to its source. Cold startup may create
and delete `$$$.SUB` on private boot copies; this expected scratch activity is
separate from the byte-identical filesystem check across SYSGEN. All release
masters are checked unchanged.

Final gate results, archive index, exact hashes and reuse boundaries are pinned
in [the evidence summary](evidence/1.3-install-911/summary.json). Evidence belongs
to its stated producer; subsequent validation-tool/documentation commits do not
relabel those artifacts. Committed text witnesses normalize terminal line
endings/trailing spaces; the summary retains hashes of the original captures.

The eight downloadable review archives remain `CANDIDATE; NOT ACCEPTED`.
Technical gate results do not authorize release acceptance, tag creation,
publication, baseline promotion or PR merging. Maintainer review of the startup
fix and release acceptance remain required.
