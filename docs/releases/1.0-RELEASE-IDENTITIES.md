# BetterCP/M 1.0 release identities

The maintainer authorized release identity promotion and replacement-package
qualification after PR #608. The six frozen archives from
`54c503652fa957798bf2d0d636f4172851195926` remain an immutable qualified
reference with their recorded development-identity exception. They must not be
overwritten. Replacement archives require fresh hashes and acceptance receipts.
No release tag or publication is authorized by this work.

The package/distribution version is 1.0. It does not replace independent module,
subsystem or utility versions. The historical core source milestone in
`metadata/core-1.0.json` remains unchanged. Exact artifacts and their source
revision, rather than the aggregate banner alone, identify the distribution.

Each promoted utility receives one explicit next revision. This is a release
assignment, not a compilation counter. Selected-input baselines allow automatic
release display for these inputs; changed or unknown inputs retain development
markings. No forced assigned-display override is used. Baselines alone are not
execution qualification.

R, W and MOUNT now have registry-owned identities generated in the reconstructed
pinned offline source. The original upstream patches and emulator execution
sources are unchanged. Guest fingerprints use the assembler actually built
from that source. Both help and version occurrences must be present before
substitution; unexpected source layout fails closed.

RCP's normal VER heading displays BetterCP/M 1.0 only with matching release
inputs, retaining its development fallback otherwise. Its fixed-size heading
field preserves following offsets. The short startup Core OS 1.0 banner remains.

FDB retains 1.0 (001) only if its COM and matching viewer overlay remain identical
to the PR #608 qualified pair. NOAH and existing module/subsystem identities are
retained only subject to comparison with their qualified artifact hashes. The
53K cpmsim RAM profile remains selected; fullram/56K remains deferred.

The 35c56a03 lock is historical evidence for matching binaries. Identity-promoted
utilities have different hashes and need explicit affected qualification; they
must not be reported as matching that old binary lock. Final replacement media,
offline Source reconstruction and native workflows require separate receipts.
