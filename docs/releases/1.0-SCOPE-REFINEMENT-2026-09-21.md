# BetterCP/M 1.0 scope refinement — 21 September 2026

## Decision

BetterCP/M 1.0 will be a qualified system release rather than the simultaneous
completion of every planned architectural facility. Work already central to
the two supported platforms remains in scope; large independent feature
programs that have not entered implementation move to later 1.x releases.

## Retained for 1.0

- complete stateful RSX reconstruction and stable CPX/RSX interfaces;
- CP/M 2.2 core compatibility on trs80gp/Model 4 and z80pack/cpmsim;
- at least 53 KiB default usable TPA;
- the defined execution-in-place ROM qualification profile;
- the existing bounded persistent command history and required SUBMIT/XSUB;
- normalized disk state, FDF/FDB, CONFIG, DUP, SYSGEN, and installation;
- required CP/M file-attribute behavior;
- P2DOS-compatible Functions 200/201, `TIME.COM`, and qualified read-only FreHD
  and z80pack clock-provider RSXs;
- reassignment of private CPX control away from historical P2DOS Function 200
  and removal of the HELLO/ECHO proof selectors from the released namespace
  before the 1.0 ABI freeze; and
- a small explicit utility and disk inventory followed by release qualification.

## Deferred to later 1.x

- `HISTORY.RSX` redesign;
- named directories, PATH, NDR management, and command integration;
- a general dynamic PDS allocator, migration, and runtime expansion;
- a required writable clock provider and successful clock setting on the two
  release platforms;
- DateStamper, ZSDOS/ZDDOS, broader P2DOS, CP/M Plus, and DOS+/Z80DOS
  compatibility adapters; and
- native or legacy filesystem timestamps, timestamp editing, and related host
  tooling.

Except for the standard Functions 200/201 clock interface, the deferred
date/time families remain compatibility candidates, with DateStamper and
ZSDOS/ZDDOS first. Clock access and filesystem timestamps are separate features
and must not be reported as equivalent.

## Required pre-freeze decision

BetterCP/M currently assigns private CPX control to BDOS Function 200, which
historical P2DOS uses for get-time. The nonproduction HELLO proof uses Function
201, which P2DOS uses for set-time, and ECHO uses Function 203 as a second RSX
chain test. Before the 1.0 extension namespace is frozen, inventory it
completely, move the private services to Functions 176-199, remove both proof
selectors from the released namespace, rebuild their clients, and implement
200/201 with their inherited P2DOS get/set clock meanings. Test-only selectors
remain explicitly experimental. The 1.0 promise covers these clock calls, not
P2DOS file timestamps or broader operating-system emulation.

## Rationale

The clock path is already implemented far enough that adapting it preserves
useful, bounded work: `TIME.COM`, two platform providers, calendar checks, and
physical FreHD qualification exist. Other historical clock APIs and filesystem
timestamp schemes remain later work and cut across BDOS dispatch, directory
layouts, copying, CONFIG, disk tools, cpmtools interoperability, and multiple
incompatible conventions.

The same rule applies elsewhere: retain infrastructure required for a stable,
portable release, while allowing independently useful facilities to arrive in
minor releases with their own memory and compatibility evidence.
