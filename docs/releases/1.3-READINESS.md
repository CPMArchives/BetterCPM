Status: review candidate, not a release acceptance or publication claim.
The merged feature baseline is `bcd27a0a` (PR #687). This stage corrects
candidate identities, packaging paths, user guidance and demonstrated blockers.
The [evidence summary](evidence/1.3-readiness/summary.json) pins source commits,
actual image hashes, free space, memory boundaries and observed smoke results.

## Focused evidence and reuse boundaries

Fresh three-platform System construction passes independent membership,
allocation/file readback and configuration checks. Default record-aligned COM
limits are exactly **57344 bytes** for cpmsim/Model II and **54272 bytes** for
Model 4; the next record is rejected and protected canaries remain intact.
Defaults remain H192/M0/V0, 12 metadata bytes and 204 total PDS bytes.

The repaired cpmsim and Model II Systems pass boot/identity, CONFIG F, default
memory, NDR/PATH, HELP VAR and ordinary transient smoke. cpmsim uses a disposable
Companion C: fixture containing the matching built HELP archive; this does not
qualify the eventual complete Companion Utilities package. Model II retains
its existing empty saved startup command; the smoke issues VER explicitly.

Model 4's prior full smoke passes on the preceding candidate. Only HELP.COM
changes in the rebuilt System inventory. Its final-media HELP delta smoke
repeats boot/identity, unloaded memory, HELP VAR and ordinary COM; all unchanged
members retain their exact prior hashes. The supplied default startup's ADM3A
is unloaded before measuring the policy floor. All smoke runs use private
copies and leave the original image hashes unchanged.

Runtime release-query/selector checks preserve IX/SP. The final emitted Model II
kernel also passes optional VAR/MCL cold/warm, substitution, SUBMIT/XSUB,
NDR/PATH, GET/POKE and exact optional COM fit/overflow cases with controlled
physical transfers. Existing PR #683–#687 evidence remains relevant for
unchanged functional inputs; no broad qualification campaign is repeated.

## Remaining release gates

The same stale PATH binding is present in NOAH's overlay locator. A production
fixture fails to find a matching overlay in active C4: from B7:. The separate
[PR #688](https://github.com/CPMArchives/BetterCPM/pull/688) proposes the narrow
repair, a matching 1.0 (022) COM/OVL pair and 36 passing PATH cases. Because the
locked scope explicitly names 021, that identity exception requires maintainer
review. Published 021 artifacts are unchanged. This readiness PR deliberately
does not silently replace them or call the current full distribution ready.

Native RLMBUILD also still takes the unpacked inner CCP length with the packed
outer relocation count, uses 5632-byte input slots and always writes a two-sector
header. It cannot reconstruct the current packed CCP. A separate native-builder
repair is required before final Source/System acceptance.

After review/merge, freeze the final combined source, select the approved NOAH
pair, build matching Utilities/Companion media and audit all eight final
archives, source offers, offline-runtime provenance and Documentation selection.
Complete final installation/package acceptance and maintainer sign-off. Candidate
construction/smoke receipts are not a substitute for those final gates. No tag,
publication, historical lock rewrite, baseline promotion or PR merge is performed
by this work.
